# Task 5 实施报告：用户端账号、钱包与可信支付结果

## 交付结果

- 用户端已从开发演示登录切换到正式手机号账号接口：短信验证码注册、自设密码登录、当前设备退出和全部设备退出。
- Access Token 仅保存在页面内存；Refresh Token 只通过 HttpOnly Cookie 使用，不再把 Token 或用户资料写入 `localStorage`。
- HTTP 层启用跨域凭据，遇到并发 401 时只发起一次 Refresh 请求；刷新成功后重放原请求，刷新失败才清理会话并打开登录框。
- WebSocket 改为复用内存 Access Token，不再从本地存储读取凭据。
- 新增普通用户可见的模拟钱包页面，展示可用余额、冻结金额、模拟金领取和双向账本流水。
- 模拟金领取在网络失败后保留原幂等键，用户重试不会重复入账。
- “我的”页面展示钱包余额入口，并在会话清理时同步清空钱包和支付恢复状态，避免跨账号残留。
- 下单页、订单列表和订单详情均切换到 `POST /user/orders/{id}/payments`；旧 `/user/order/payment` 前端旁路已移除。
- 支付结果页不再采信 URL `success` 参数，只显示服务端 `GET /user/payments/{paymentNo}` 返回的可信状态。
- 支付状态按 1、2、3、5 秒退避轮询，最长 30 秒；超过时提示稍后从订单查看，查询失败可重试，余额不足可进入钱包领取模拟金。
- 支付创建幂等键和支付号保存在当前浏览器会话，可在创建响应丢失或页面刷新后恢复查询。

## 界面与交互

- 继续使用现有中式餐饮视觉令牌，没有引入无关的全站换肤。
- 新增钱包余额卡和流水列表的桌面、手机响应式布局。
- 关键按钮具有至少 44px 触控高度、加载禁用态、可见焦点和明确错误恢复入口。
- 装饰图标使用 Lucide SVG 并从辅助技术中隐藏；支付状态同时使用图标和文字，不只依赖颜色。
- 延续项目已有 `prefers-reduced-motion` 规则；页面按路由懒加载，钱包不会增加首屏同步负担。
