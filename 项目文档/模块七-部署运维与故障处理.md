# 模块七：部署、运维与故障处理

## 1. 范围与运行边界

本文是第一阶段管理端 AI 助手的统一运行手册，覆盖首次部署、启动停止、升级回滚、健康检查、测试、备份恢复和常见故障定位。

当前交付是单机 Docker Compose，不是高可用集群。`sky-agent` 必须保持一个 Uvicorn worker：任务队列、运行任务和部分状态仍依赖单进程内存与本地 SQLite；直接增加 worker 会导致任务状态、取消和 SSE 订阅落到不同进程。扩容前必须先将这些状态迁移到共享存储，本阶段不得用多 worker 规避容量限制。

权威业务数据仍在 Java/MySQL。Python Agent 只保存模型执行、索引任务和知识源运行数据，不应被当作订单或员工数据权威来源。

## 2. 部署前提

- Docker Engine 或 Docker Desktop 正常运行，并支持 `docker compose`。
- Java 构建镜像使用 Java 21；本机只运行 Compose 时无须另装 Java。
- BGE-M3 模型约 4.27 GB。建议至少预留 10 GB 可用磁盘和 12 GB 系统内存；CPU 首次加载可能持续数分钟。
- 可以访问配置的 OpenAI 兼容 LLM 地址。
- 生产环境应限制 MySQL、Redis、Qdrant、Agent、Embedding 和观测端口的公网访问，只暴露必要入口。

部署前检查：

```powershell
docker version
docker compose version
docker info
```

## 3. 首次部署

### 3.1 创建环境文件

在项目根目录执行：

```powershell
Copy-Item .env.example .env
```

必须替换数据库密码、Redis 密码、两个 JWT 密钥、LLM 模型和 API Key，以及启用观测组件时的 Grafana 密码。JWT 密钥至少 32 字符，可分别生成：

```powershell
[Convert]::ToHexString(
  [Security.Cryptography.RandomNumberGenerator]::GetBytes(48)
).ToLowerInvariant()
```

检查是否仍有示例占位值；命令正常情况下不应返回匹配行：

```powershell
Select-String -Path .env -Pattern 'replace-with|change-me'
```

`.env` 只保存在部署机器，禁止提交版本库、粘贴到工单或写入镜像。环境变量分类如下：

| 类别 | 关键变量 |
| --- | --- |
| 应用模式 | `SPRING_PROFILES_ACTIVE`、`APP_ENV`、`AI_ENABLED`、`CORS_ALLOWED_ORIGINS` |
| MySQL | `DB_*`、`MYSQL_*`、`MYSQL_PORT` |
| Redis | `REDIS_*` |
| 认证 | `JWT_ADMIN_SECRET`、`JWT_USER_SECRET` |
| LLM | `LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_ALLOWED_MODELS`、`LLM_API_KEY` |
| LLM 治理 | `LLM_*TIMEOUT*`、`LLM_MAX_*`、`LLM_FALLBACK_MODEL`、价格和温度配置 |
| RAG | `QDRANT_COLLECTION`、`RAG_ENABLED`、`RAG_TOP_K`、`RAG_SCORE_THRESHOLD` |
| Embedding | `BGE_MODEL_HOST_PATH`、`EMBEDDING_MODEL`、维度、批大小和设备 |
| 镜像/卷 | `SKY_*_IMAGE`、`*_VOLUME_NAME` |
| 观测 | `PROMETHEUS_*`、`GRAFANA_*` |

完整变量、默认值和示例以根目录 `.env.example` 为准。更改 `.env` 后必须重新创建相关容器，已运行容器不会自动刷新环境。

### 3.2 准备并校验 BGE-M3

从受信任的制品源取得 `BAAI/bge-m3` revision：

```text
5617a9f61b028005a4858fdac845db406aefb181
```

将完整模型放在 `sky-embedding/models/bge-m3`，或把 `.env` 中的 `BGE_MODEL_HOST_PATH` 指向其他绝对目录。Compose 只读挂载该目录，不在启动时下载模型，也不把权重复制进镜像。

校验固定版本的关键权重和 tokenizer：

```powershell
.\scripts\verify-bge-model.ps1
```

如模型位于其他目录，将 `.env` 的 `BGE_MODEL_HOST_PATH` 改为该目录，并把同一路径传给 `-ModelPath`。

只有输出 `"status": "verified"` 才能继续。manifest 位于 `sky-embedding/model-manifest.example.json`；更换模型 revision 时必须同步更新 revision、文件大小和 SHA-256，并先完成质量回归。

### 3.3 配置预检与启动

以下命令只验证配置，不输出渲染后的密钥：

```powershell
docker compose -f compose.yml config --quiet
```

启动完整本地模式：

```powershell
docker compose -f compose.yml up -d --build
docker compose -f compose.yml ps
```

Embedding 在 CPU 上加载时间最长。`starting` 期间的 readiness 503 是预期行为；以所有必需服务最终显示 `healthy` 为准，不以容器仅处于 `running` 为准。

### 3.4 首次验收

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health/ready
Invoke-RestMethod http://127.0.0.1:8000/health/ready
Invoke-RestMethod http://127.0.0.1:8080/actuator/health/readiness
docker compose port qdrant 6333
```

随后登录管理端，上传一份非敏感测试知识文档，等待索引完成，提交问题并确认：

1. 收到结构化 SSE 结束事件。
2. 答案正文正常。
3. 引用指向授权知识库中的正确文档。
4. 以相同 `task_id` 能关联 Java、Agent、Embedding 和 LLM 日志。

## 4. 外部基础设施模式

先设置外部 MySQL、Redis 和 Qdrant 地址，再启动三个应用服务：

```powershell
docker compose -f compose.yml -f compose.external.yml config --quiet
docker compose -f compose.yml -f compose.external.yml `
  up -d --build sky-embedding sky-agent sky-server
```

覆盖文件把本地 MySQL、Redis 和 Qdrant 放入不默认启用的 `local-infrastructure` profile；明确的应用服务列表仍应保留。三个应用默认使用 Compose 服务名互联。只有 Embedding 或 Agent 本身也部署在外部时，才分别设置 `EXTERNAL_EMBEDDING_BASE_URL` 或 `EXTERNAL_AGENT_BASE_URL`，并使用 `--no-deps` 启动实际需要的本地服务。外部地址不能写 `localhost`，除非目标确实与调用容器处于同一网络命名空间。外部 Qdrant 集合维度必须为 1024。

## 5. 日常启动、停止与日志

```powershell
# 启动现有容器
docker compose start

# 查看状态和最近日志
docker compose ps
docker compose logs --tail=200 sky-server sky-agent sky-embedding

# 跟随单个任务；把值替换为实际 task_id
docker compose logs --since=30m sky-server sky-agent sky-embedding |
  Select-String 'actual-task-id'

# 正常停止，保留容器和卷
docker compose stop
```

不得把 `docker compose down -v` 当作日常停止命令；`-v` 会删除 MySQL、Redis、Qdrant、Agent 和 Server 命名卷。确需销毁环境时必须先备份并单独确认卷名。

指标入口：Java `/actuator/prometheus`、Agent `/metrics`、Embedding `/metrics`、Qdrant `/metrics`。可选观测组件启动命令：

```powershell
docker compose --profile observability up -d prometheus grafana node-exporter
```

## 6. 升级与回滚

### 6.1 升级

1. 执行并校验备份。
2. 运行 Java/Python 测试及模块六质量门禁。
3. 为三个应用设置不可变版本标签，例如 `sky-server:20260912-1`，不要复用生产版本标签。
4. 构建镜像并记录 Git commit、镜像标签和部署时间。
5. 重新创建应用容器，检查 readiness 和一次带引用问答。

```powershell
docker compose build sky-server sky-agent sky-embedding
docker compose up -d --no-deps sky-embedding
docker compose up -d --no-deps sky-agent
docker compose up -d --no-deps sky-server
docker compose ps
```

`SKY_SERVER_IMAGE`、`SKY_AGENT_IMAGE`、`SKY_EMBEDDING_IMAGE` 决定构建和运行标签。先升级 Embedding，再升级 Agent，最后升级 Java，可缩小依赖协议不兼容的诊断范围。

### 6.2 回滚

把 `.env` 中三个 `SKY_*_IMAGE` 改回上一组已验证标签，然后执行：

```powershell
docker compose up -d --no-build --no-deps sky-embedding sky-agent sky-server
docker compose ps
```

应用回滚不自动回滚数据库。Flyway 迁移若不向后兼容，应停止写入并从升级前备份恢复到隔离实例验证后再切换，禁止直接修改 Flyway 历史表或覆盖运行中的生产卷。

## 7. 测试与发布检查

```powershell
# Java 单元与契约测试
mvn test

# Python 单元、协议测试
Push-Location sky-agent
python -m unittest discover -s tests -v
Pop-Location

# 真实 Embedding + Qdrant + Mock LLM 全量门禁
.\scripts\run-quality-eval.ps1 -Mode mock

# 显式真实 LLM 小样本门禁
.\scripts\run-quality-eval.ps1 -Mode real -RealSampleSize 12 `
  -Output build/reports/rag-eval-real.json
```

真实 LLM 测试会产生调用和费用。发布必须同时满足模块六门槛，不能仅凭容器健康状态发布。

## 8. 备份与恢复

### 8.1 备份

备份目录不得放在项目、Docker 卷或待升级磁盘中：

```powershell
$backupRoot = Join-Path ([Environment]::GetFolderPath('UserProfile')) 'sky-backups'
$backup = .\scripts\backup-ai-runtime.ps1 -BackupDirectory $backupRoot |
  Select-Object -Last 1
.\scripts\verify-backup.ps1 -BackupPath $backup
```

备份包含 MySQL 逻辑导出、Qdrant 各集合快照、Agent 数据卷归档、结构化 `SHA256SUMS.json` 和便于人工使用的 `SHA256SUMS.txt`。校验失败的备份不可用于恢复。

### 8.2 恢复原则

1. 停止 `sky-server` 和 `sky-agent`，阻止新写入。
2. 校验备份文件。
3. 在空 MySQL、空 Qdrant 集合和空 Agent 卷的隔离环境恢复。
4. 启动 Java，让 Flyway 检查版本；验证任务、历史消息和一次带引用问答。
5. 验收通过后再安排生产切换。

```powershell
docker compose stop sky-server sky-agent
.\scripts\verify-backup.ps1 -BackupPath $backup
```

MySQL 使用备份中的 `mysql.sql` 导入空数据库。Qdrant 按 `qdrant-snapshots.json` 中的集合与快照对应关系调用 snapshot upload/recovery API。Agent 的 `agent-data.tar.gz` 只能解压到新建的空卷。禁止覆盖正在运行的生产数据库、集合或卷。

自动隔离演练：

```powershell
.\scripts\test-backup-restore-drill.ps1
```

成功标志为 `DRILL_SUCCESS: mysql, qdrant, agent-volume, checksums`。每次生产升级前以及至少每季度执行一次，并记录备份标识、耗时、操作者和验证结果。

## 9. 常见故障处理

| 现象 | 定位 | 处理 |
| --- | --- | --- |
| Embedding 长时间 `starting` | 查看 `sky-embedding` 日志、模型挂载和内存 | 运行模型校验；确认挂载目标 `/models/bge-m3` 只读且内存充足 |
| Embedding 显示 `failed` | `/health` 的错误摘要和容器日志 | 检查 revision、权重文件、设备设置；CPU 环境保持 `EMBEDDING_DEVICE=cpu` |
| Qdrant 集合维度不匹配 | Agent readiness/日志出现 expected 1024 | 备份旧集合，创建新集合并重新索引；不要直接删除生产集合 |
| Agent readiness 503 | 分别请求 Qdrant、Embedding 健康端点 | 修复失败依赖；依赖恢复后 Agent readiness 应自动恢复 |
| LLM 401/403 | 日志错误类型 `AUTH_FAILED` | 检查提供商、Key 权限和容器是否已重新创建；不得在日志打印 Key |
| LLM 429/5xx/超时 | `RATE_LIMITED`、`UPSTREAM_5XX`、`TIMEOUT` 指标 | 检查退避、并发、总超时和提供商状态；不要无限重试 |
| SSE 中断 | 用 `task_id` 对照 Java/Agent 事件和 LLM 流日志 | 判断是浏览器断开、Java 转发、Agent 取消还是 LLM 流中断；已有输出后不得重试拼接 |
| MySQL/Flyway 启动失败 | `sky-server` 日志和 Flyway 历史表 | 检查数据库权限、连接地址和迁移校验；禁止手工改历史表 |
| Redis 不可用 | Java readiness 和 Redis 容器日志 | 检查密码、AOF、磁盘及 `redis:6379` 容器网络地址 |
| 问答无引用或错误引用 | 运行模块六报告并查看逐题来源 | 检查授权版本范围、阈值、Embedding revision 和 Qdrant 集合，不要先降低发布门槛 |
| 磁盘增长 | `docker system df`、卷和日志大小 | 按保留策略清理旧备份/指标；先确认归属，禁止直接删除活动卷 |

推荐按以下顺序定位：`docker compose ps` → 应用 readiness → 依赖健康 → 带 `task_id` 的日志 → 指标与告警 → 配置差异。不要通过关闭鉴权、取消版本过滤或把密钥打印到日志来临时绕过问题。
