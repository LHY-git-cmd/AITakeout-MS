# 用户端全链路优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分四个可独立验收的阶段，将当前用户端演示链路升级为包含正式账号、权威试算、生产级模拟支付、取消退款、售后、通知、搜索和个人资料的完整交易系统。

**Architecture:** 保留 Spring Boot、MyBatis、MySQL、Vue 3 和 WebSocket，按账号、支付、账户、配送、订单、售后和通知划分模块化单体边界。核心交易使用本地事务、期望状态条件更新、幂等键和双向账本；支付、地图、短信通过适配器切换模拟实现与真实厂商实现。

**Tech Stack:** Java 17、Spring Boot 3.5.16、MyBatis、Flyway、MySQL/H2、JUnit 5、Mockito、Vue 3.5、Pinia、Vue Router、Vitest、Vue Test Utils、Playwright。

**Spec:** `项目文档/用户端传统业务全链路优化设计说明.md`

## Global Constraints

- 普通手机浏览器是主要终端；微信内置浏览器第一版提示在系统浏览器打开。
- 当前支付渠道为生产级模拟支付，未来通过 `PaymentGateway` 接入微信 H5。
- 新增资金金额统一使用整数“分”；账本分录不可修改和删除。
- 订单、支付、退款和售后状态独立建模。
- 支付有效期固定为 15 分钟，完成订单售后有效期固定为 24 小时。
- 模拟账户初始余额 50000 分，每次领取 50000 分，上限 1000000 分。
- 默认配送费：3000 米内 500 分，3001—5000 米 800 分，超过 5000 米不可配送。
- 本地和自动化测试使用模拟地图；联调、预发布和生产使用百度地图。
- 搜索为单页无限滚动，服务端游标分批返回，前端不显示页码。
- 通知持久化保存 90 天，WebSocket 只负责实时提醒。
- 第一版只支持整单全额退款，不支持部分退款和商家提现。
- 所有代码变更使用 TDD；每个任务先看到目标测试失败，再实现并验证通过。
- 不回退或覆盖工作区中与当前任务无关的用户修改。

## 2. 跨阶段文件结构

### 后端新增边界

```text
sky-server/src/main/java/com/sky/
├─ controller/user/       用户端 HTTP 接口
├─ controller/admin/      售后审核、异常退款和调账接口
├─ service/auth/          短信、会话、正式认证
├─ service/account/       模拟账户与双向账本
├─ service/payment/       支付单、退款单、支付渠道
├─ service/checkout/      试算、费用和下单编排
├─ service/delivery/      地图、距离和配送时段
├─ service/aftersale/     取消申请与售后
├─ service/notification/  通知、Outbox 和发布器
├─ service/catalog/       跨分类搜索
├─ mapper/                MyBatis Mapper 接口
└─ task/                  支付超时、退款重试、Outbox 和对账任务
```

数据载体继续放入 `sky-pojo`，通用错误码和配置属性放入 `sky-common`；不新建 Maven 子模块，避免引入跨模块循环依赖。

### 用户端新增边界

```text
frontend/project-sky-user-web/src/
├─ api/          按 auth、account、checkout、payment、aftersale、notification、search 拆分
├─ stores/       auth、account、checkout、notification、search 状态
├─ components/   登录、验证码、余额、时间轴、通知、地址选择等小组件
├─ views/        钱包、流水、通知、售后、资料编辑等页面
└─ utils/        金额、游标、支付轮询和错误恢复
```

### 数据库迁移

所有结构变化通过 `sky-server/src/main/resources/db/migration/` 下新的大写 `V<日期>_<序号>__<英文说明>.sql` 完成。禁止修改已经执行过的 Flyway 文件；每个阶段独立迁移，便于定位和回滚。

## 3. 阶段验收门

### 阶段一验收

- [ ] 用户可注册、登录、刷新会话、退出当前设备和全部设备。
- [ ] 密码由用户设置并使用 BCrypt，不再生成默认密码。
- [ ] 用户可看到模拟余额、领取模拟金和查看平衡流水。
- [ ] 同一订单只能支付成功一次，支付结果由服务端查询确认。
- [ ] 15 分钟超时任务不会取消已支付订单。
- [ ] 最小 Playwright 移动端支付链路通过。

### 阶段二验收

- [ ] 地址保存时始终进行地图解析和配送范围预检。
- [ ] 试算金额完全由服务端计算，并返回配送距离与时间段。
- [ ] 相同幂等键只创建一个订单。
- [ ] 商品改价、下架、门店打烊、地图超时都有可恢复错误。
- [ ] 提交订单保存商品、联系人和地址快照。

### 阶段三验收

- [ ] 待接单取消自动全额退款；制作中和配送中遵循审核规则。
- [ ] 完成后 24 小时内可申请售后，边界测试准确。
- [ ] 退款失败不会提前显示成功，也不会重复冻结资金。
- [ ] 每次业务变化都进入订单时间轴和通知中心。
- [ ] WebSocket 断线后通知可补拉。

### 阶段四验收

- [ ] 地址三级联动、资料编辑、头像上传和手机号换绑可用。
- [ ] 搜索无限滚动不重复、不遗漏，并恢复滚动位置。
- [ ] Chrome 和 WebKit 移动端全链路 E2E 通过。
- [ ] 资金对账零差异，没有未处理的支付、退款或 Outbox 异常。
- [ ] 旧演示登录和固定 0.01 元退款旁路已移除。

## 4. 全局执行流程

每个任务统一执行以下循环：

1. 阅读设计说明、当前阶段计划和任务涉及的现有文件。
2. 写出一个只验证当前行为的失败测试。
3. 运行精确测试，确认失败原因来自缺少目标能力。
4. 实现最小代码，避免顺带重构无关模块。
5. 运行精确测试、所属模块测试和静态检查。
6. 检查 `git diff`，确认未覆盖用户已有修改。
7. 使用小而完整的提交保存该任务。
8. 由独立审查检查需求符合性，再检查代码质量。

## 6. 发布与回滚原则

- 数据库先采用向前兼容迁移，再发布后端，最后发布前端。
- 新旧接口并存一个阶段；新前端稳定且对账无差异后才移除旧接口。
- 代码回滚不得删除资金账本和交易记录；只能停止新入口并用反向流水修正数据。
- 支付、退款或对账异常时关闭新支付入口，但保留订单查询和通知查询。
- 百度地图异常时阻止新订单提交，不得绕过配送范围校验。
- 每个阶段输出实施报告，记录提交、迁移版本、验证命令、结果和未解决风险。
