**阶段一：知识库构建 (一次性或低频操作)**
这个阶段发生在管理员创建或更新知识库时，是一个预处理步骤。

上传文档：管理员在系统中上传一个或多个文件（如PDF, Word, Markdown等）到一个知识库。

文本提取与分块 (Chunking)：
Java后端将这个任务发送给Python服务。
Python服务首先从文件中提取出纯文本。
然后，根据您在 KnowledgeBaseDTO 中定义的 chunkStrategy（分块策略），将长文本切分成许多个小的、
有意义的文本块（Chunks）。例如，每三句话一段，或者每个段落一段。

向量化 (Embedding)：
Python服务遍历每一个文本块。
对于每一个块，它会调用您在 KnowledgeBaseDTO 中指定的 embeddingModel（向量模型），将这个文本块转换成一个数学向量（一长串数字）。

存入向量数据库 (Indexing)：
Python服务将生成的向量和原始文本块作为一条记录，存入向量数据库（例如Qdrant）。
所以，数据库里存储的是大量的 { "向量": [...], "原始文本": "这是文本块A的内容..." } 这样的键值对。
这个阶段完成后，知识库的内容就已经被“消化”并准备好了，可以被快速检索。

**阶段二：实时问答 (高频操作)**
这个阶段发生在用户每次提问时。

用户提问：用户在前端输入问题，例如：“红烧牛肉面有什么特点？”
问题向量化：
请求被发送到Python服务。
Python服务使用同一个embeddingModel，将用户的问题本身也转换成一个向量（我们称之为“查询向量”）。

相似度搜索 (Retrieval)：
Python服务拿着这个“查询向量”去向量数据库（Qdrant）里进行搜索。
向量数据库会快速计算“查询向量”与数据库中所有“文本块向量”的相似度，并返回最相似的Top-K个结果（例如最相似的5个文本块）。

构建Prompt (Augmentation)：
Python服务现在拿到了用户的原始问题和5个最相关的知识片段。
它会构建一个新的、信息量丰富的Prompt，发送给大语言模型（LLM）。这个Prompt看起来像这样：
text



请根据以下背景知识来回答用户的问题。

背景知识:
1. "红烧牛肉面选用上等牛腩，经过慢火炖煮..."
2. "我们的面条是手工制作，口感劲道..."
3. (其他相关的文本块)

用户问题:
"红烧牛肉面有什么特点？"
生成答案 (Generation)：
LLM接收到这个增强后的Prompt，根据提供的背景知识，生成一个准确、详细的回答。
这个回答再通过SSE流式返回给前端。
总结
简单来说：

**构建时：文件 -> 分块 -> 逐块向量化 -> 存入向量数据库 (慢过程，一次性)
问答时：问题 -> 向量化 -> 搜索相似文本块 -> 组合Prompt -> LLM生成答案 (快过程，每次都做)**
