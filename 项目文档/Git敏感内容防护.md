# Git 敏感内容防护

`.gitignore` 不会移除已经跟踪或已经推送的文件；删除最新版本中的文件也不会删除历史版本。

## 克隆后的本地防护

在项目目录使用 PowerShell 执行：

```powershell
# 配置只影响本机 Git；绝对钩子路径可同时保护本仓库的独立工作目录。
git config core.hooksPath ((Resolve-Path .githooks).Path -replace '\\', '/')
python scripts/check-git-security.py HEAD
```

推送前会检查提交的完整可达历史，拒绝私有环境文件、运行数据、上传的知识文件、日志、IDE 状态、构建输出，以及明显的令牌和配置字面凭据。检查只输出文件路径和规则，不输出敏感值。GitHub 上还有对应的只读 CI 检查。

`data/diet-seed` 是明确标记的模拟数据集，保留跟踪；`data/knowledge` 等上传和运行数据不应跟踪。不要用批量移除整个索引的方式处理这两类内容。

## 历史清理后的协作

- 已重写历史的仓库应重新克隆；需要保留未提交工作时，先将改动保存到项目外私有位置，再在新克隆中逐项应用并检查。
- 不要把旧分支整体合并回清理后的分支，否则旧敏感历史会再次可达。
- 本地旧备份分支和独立工作目录保留私有，迁移到清理后的历史之前不要推送。
- GitHub 的 PR 只读引用、缓存和其他人的 Fork/克隆无法通过普通 Git 推送清除，需要托管平台和相应副本持有者处理。
- 对于已经暴露的实际密码或密钥，应在供应商及服务端撤销或轮换。历史重写不能撤回他人已经下载的凭据。

检查规则用于降低再次泄露风险，不能替代人工审查和平台端的密钥保护。不得用跳过钩子的方式推送检查失败的旧历史。
