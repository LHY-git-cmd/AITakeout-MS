## 3. 固定协议基线

### 3.1 事件信封

| 线上字段 | Java 字段 | 规则 |
| --- | --- | --- |
| `task_id` | `taskId` | 必填，任务唯一标识 |
| `trace_id` | `traceId` | 可选；用于跨服务日志关联 |
| `seq_no` | `seqNo` | 同一任务从 1 开始严格递增 |
| `event` | `event` | 事件类型 |
| `data` | `data` | 事件载荷 |

事件唯一键为 `task_id + seq_no`。SSE `id` 等于 `seq_no`，恢复请求通过 `Last-Event-ID` 传入最后成功处理的序号。

### 3.2 终态映射

| 终态 | Python | Java/MySQL | 终止事件 |
| --- | --- | ---: | --- |
| 完成 | `completed` | 2 | `task_end` |
| 失败 | `failed` | 3 | `task_error` |
| 取消 | `cancelled` | 4 | `task_cancelled` |

排队 `pending/0` 和执行中 `running/1` 都不是终态。SSE 连接结束不等于任务完成；最终结论必须来自终止事件或 Java 任务详情。

### 3.3 HTTP 分类

| 状态 | 固定语义 |
| ---: | --- |
| 401 | 未认证或内部服务认证失败 |
| 403 | 已认证但无权访问 |
| 409 | 任务或确认状态冲突 |
| 503 | Agent 或核心依赖不可用 |

#### 模块七执行约定

使用 scripts/run-agent-v1-acceptance.ps1 生成本批次的 JSON 证据。脚本会先记录 Compose
config/up/ps、容器健康、四个 readiness 端点和 AGENT_INTERNAL_SERVICE_TOKEN 哈希一致性。
未提供场景执行器时，E2E-01 至 E2E-12 必须保持“未执行”，脚本退出码为 2，不得据此宣称通过。

场景执行器只能创建带批次前缀 agent-v1-acceptance-<批次> 的隔离数据，并在输出中列出
created_ids、任务/会话/管理员、事件序列和 Java/MySQL 最终状态。清理时只允许将该清单
传给精确 ID 清理流程；deleted_ids 去重后必须与 created_ids 集合完全相等；禁止全表删除、按模糊条件删除、清空 Qdrant 集合或删除 Docker 卷。

每个 E2E 场景还应记录：请求时间线、SSE 最后序号与 Last-Event-ID、确认凭证及审计记录、
故障注入和恢复时间、页面提示截图或脱敏接口响应。失败或环境不可用必须记录为“失败”或
“阻塞”，并附证据路径和下一步，不得改成“有条件通过”。
