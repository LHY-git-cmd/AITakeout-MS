# 阶段三：取消、退款、售后与通知实施报告

## 2. 技术选型声明

1. 订单履约、支付、退款和售后状态分开保存，订单履约转换由 `OrderStateMachine` 集中校验，所有成功转换写入订单时间轴。
2. 退款使用“先冻结来源资金、成功后释放到用户账户、失败时保留冻结并复用原退款单”的双向账本模型，避免重复冻结和超额返还。
3. 通知采用持久化记录、Outbox 和 WebSocket 提醒组合；HTTP 列表是最终事实来源，WebSocket 断线或推送失败不会造成通知丢失。

## 3. 数据库变更

迁移文件：`V20260921_01__add_after_sale_refund_notification.sql`。版本号晚于阶段二迁移，避免已部署环境发生 Flyway 迁移顺序冲突。

新增四张表：

- `after_sale_request`：保存取消/售后申请、申请前订单状态、审核结果和关联退款单；生成列唯一约束保证同一订单只有一个进行中申请。
- `refund_transaction`：保存退款业务键、支付单、资金来源、目标账户、金额、冻结与释放流水、渠道结果及下次重试时间。
- `user_notification`：保存用户可补拉通知、已读时间、订单关联和业务幂等键。
- `outbox_event`：保存待发布事件、重试次数、下次执行时间、发布结果和死信原因。

订单时间轴沿用阶段一的 `order_timeline_event`，退款、Outbox 和时间轴均不依赖物理删除恢复业务状态。

## 4. 订单状态机和时间轴

新增集中订单状态机，使用期望状态条件更新阻止并发覆盖，并为支付、取消、售后、退款和完成结算写入时间轴。存在待审核取消或售后申请时，不允许继续配送或完成订单。

订单完成时，按订单实付金额将平台待结算账户资金转入商家账户；状态转换、账本流水和时间轴在同一事务中完成，重复请求不会重复结算。

用户可通过 `GET /user/orders/{orderId}/timeline` 查询本人订单时间轴，接口会校验订单归属。

## 5. 取消和售后规则

| 订单状态 | 处理方式 | 退款规则 |
| --- | --- | --- |
| 待付款 | 直接取消 | 未付款，无需退款 |
| 待接单 | 自动取消 | 整单全额退款 |
| 制作中 | 提交审核 | 审核通过后整单全额退款 |
| 配送中 | 提交审核 | 审核通过后整单全额退款 |
| 已完成 | 实际送达后 24 小时内申请 | 审核通过后整单全额退款，订单仍保持完成 |

完成订单以实际送达时间为起点计算，达到 24 小时时即视为过期。申请原因必填，同一订单不能重复创建进行中的申请；拒绝审核时拒绝原因必填。

用户接口支持申请、查询最新申请、游标加载申请记录和查询本人退款单。管理接口支持状态筛选、详情、批准/拒绝和原退款单重试，查询使用 `ORDER_READ` 权限，审核与重试使用 `ORDER_STATUS_WRITE` 权限。

## 6. 全额退款和失败恢复

退款金额固定取成功支付单的实付金额，前后端均不提供修改退款金额的入口。退款来源根据履约阶段选择：未结算订单从平台待结算账户退款，已完成订单从商家账户退款。

处理顺序：

1. 以退款业务键创建唯一退款单。
2. 冻结来源账户的整单退款金额并记录账本流水。
3. 调用 `RefundGateway` 执行渠道退款。
4. 成功时将冻结资金转入用户可用余额，更新支付状态并发送成功通知。
5. 失败时保留冻结资金、失败原因和下次重试时间，不显示为已退款。
6. 自动任务或管理员重试时复用原退款单和原冻结记录，不再次冻结。

模拟退款由 `MockRefundGateway` 提供，业务层只依赖 `RefundGateway` 接口。因此后续接入微信支付时，可新增条件装配的 `WeChatRefundGateway`，无需重写售后规则和账本流程。

## 7. 持久化通知与 Outbox

业务事务同时写入 `user_notification` 和 `outbox_event`。Outbox 发布失败按 1、2、4、8、16 分钟退避，累计 8 次后标记为 `DEAD`，保留记录供排查。通知默认保留 90 天，清理任务不删除订单时间轴或 Outbox 死信。

WebSocket 只发送事件 ID、类型、通知 ID 和创建时间等轻量信息；客户端收到后刷新未读数和相关订单。连接恢复后，客户端通过 HTTP 补拉通知，因此离线、刷新页面或实时推送失败均不会丢失事实记录。

通知接口提供游标列表、未读数量、单条已读和全部已读。

## 8. 用户端移动体验

- 订单列表和详情根据订单状态展示取消或售后入口。
- 申请弹窗说明处理规则，提交失败时保留用户输入。
- 订单详情展示售后状态、全额退款金额和完整时间轴。
- 退款失败明确显示系统自动重试，不显示“已退款”。
- 新增通知中心、未读角标、断线补拉和退款售后记录页。
- 底部主导航保持五项以内，并处理移动安全区、触控目标、语义标签和减少动画偏好。

界面实现按 `ui-ux-pro-max` 的错误恢复、触控、可访问性和移动 Web 性能规则检查；本地 Vue 专项检索没有额外匹配项，因此采用该技能的通用 Vue 与移动浏览器准则。

## 9. 管理端售后审核

管理端新增售后列表和详情页，支持按状态筛选并查看申请原因、订单金额、退款单和处理状态。批准前再次确认整单退款金额；拒绝必须填写原因；退款失败时只能重试原退款单，不能修改退款金额。

## 10. 自动任务和测试隔离

- `RefundRetryTask`：扫描到期失败退款并复用原退款单重试。
- `OutboxPublishTask`：批量发布待处理通知事件。
- `NotificationRetentionTask`：每日清理超过 90 天的用户通知。

三个任务都支持通过配置关闭调度。测试环境显式关闭新增调度任务，避免空 H2 数据库的后台查询干扰测试。隔离 E2E 脚本使用临时 MySQL、Redis、后端和 Vite 进程，测试完成后自动清理，不读取或修改开发数据库；SQL 夹具已经同步阶段三四张新表。

1. 新增 `WeChatRefundGateway` 并按支付渠道或生产配置启用；真实微信支付配置下必须禁止装配 `MockRefundGateway`。

4. 上线前用微信沙箱或商户测试环境验证支付成功、退款成功、退款失败、超时查询和重复回调。
