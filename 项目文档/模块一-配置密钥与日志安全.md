# 模块一：配置、密钥与日志安全

## 1. 配置入口

根目录 `.env.example` 是本阶段统一配置契约，不包含可用密钥。复制为 `.env` 仅适用于本地开发；生产环境必须由部署平台、Secret Manager 或进程环境注入，禁止把生产 `.env` 放入镜像或版本库。

配置覆盖顺序如下：

1. Java：命令行参数 > JVM System Property > 操作系统/容器环境变量 > `application-{profile}.yml` > `application.yml`。
2. Python Agent：操作系统/容器环境变量 > Agent 工作目录 `.env` > 代码中的非敏感默认值。
3. Compose：`environment` 显式值 > `env_file`/项目 `.env`；模块三编写 Compose 时不得在 YAML 中写入密钥。
4. 测试：Java 使用 `application-test.yml` 中不可用于生产的测试值；Python 单元测试按用例显式构造配置或 Mock LLM。

`SPRING_PROFILES_ACTIVE` 选择 Java 环境。生产环境不得沿用 `dev` Profile，且必须显式注入数据库账号、JWT 密钥及启用功能所需的第三方凭据。

## 2. 必填配置与启动校验

| 服务 | 配置 | 用途 | 是否敏感 |
| --- | --- | --- | --- |
| sky-server | `DB_HOST/DB_PORT/DB_NAME/DB_USERNAME/DB_PASSWORD` | MySQL 连接 | 用户名、密码敏感 |
| sky-server | `REDIS_HOST/REDIS_PORT/REDIS_PASSWORD/REDIS_DATABASE` | Redis 连接 | 密码敏感 |
| sky-server | `JWT_ADMIN_SECRET/JWT_USER_SECRET` | JWT 签名，至少 32 字符 | 是 |
| sky-server | `AGENT_BASE_URL` | Agent 地址 | 否 |
| Java/Agent | `LLM_PROVIDER/LLM_BASE_URL/LLM_MODEL/LLM_API_KEY` | 统一 LLM 配置 | API Key 敏感 |
| Agent | `QDRANT_URL/QDRANT_COLLECTION` | 向量库 | 视部署而定 |
| Agent | `EMBEDDING_BASE_URL/EMBEDDING_MODEL/EMBEDDING_DIMENSION` | Embedding 调用 | 否 |
| Embedding | `EMBEDDING_MODEL_PATH/EMBEDDING_DEVICE/EMBEDDING_MAX_BATCH_SIZE` | 模型加载与推理 | 否 |

Java 通过不可解析的必填占位符以及配置属性校验快速失败；JWT 密钥少于 32 字符会拒绝启动。Agent 在 FastAPI lifespan 初始化任何任务前统一校验四个 LLM 变量、依赖 URL、向量存储类型及数值范围，错误只报告变量名和规则，不回显值。

阿里云 OSS、微信和百度地图配置仅在对应功能启用时需要。示例中保持为空，不能使用弱默认密钥代替。

## 3. Compose 环境变量清单

模块三的 `compose.yml` 应直接复用 `.env.example` 中的命名：

- `sky-server`：`SPRING_PROFILES_ACTIVE`、`AGENT_BASE_URL`、全部 `DB_*`、`REDIS_*`、`JWT_*`、`LLM_*` 和已启用第三方服务变量。
- `sky-agent`：`APP_ENV`、`LOG_LEVEL`、`LLM_*`、`TASK_STATE_DB`、`KNOWLEDGE_STATE_DB`、`KNOWLEDGE_SOURCE_PATH`、`QDRANT_*`、`EMBEDDING_*`、`AGENT_MAX_CONTEXT_CHARS`。
- `sky-embedding`：`EMBEDDING_MODEL`、`EMBEDDING_MODEL_PATH`、`EMBEDDING_DEVICE`、`EMBEDDING_USE_FP16`、`EMBEDDING_MAX_BATCH_SIZE`。
- `mysql`：`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`。
- `redis`：`REDIS_PASSWORD`；启动参数应从环境读取，不在 Compose 文件中写明文。
- `qdrant`：本地默认无需密钥；外部实例的认证参数应通过新增 Secret 注入，不得复用 LLM 或数据库密钥。

容器内地址届时分别改为 `mysql`、`redis`、`qdrant`、`sky-agent`、`sky-embedding` 服务名；根示例当前保留 localhost，方便未容器化阶段本地运行。

## 4. LLM 日志脱敏方案

默认日志允许记录：`trace_id`（当前以任务 ID 关联）、`task_id`、`session_id`、供应商、模型、流式标记、温度、消息数量、Prompt 总字符数、输出字符数、耗时、状态、Token 数和异常类型。

默认日志禁止记录：API Key、Authorization/JWT、数据库或 Redis 密码、用户问题正文、历史消息、System Prompt、RAG 证据正文、引用原文、完整请求/响应体和包含凭据的异常摘要。

代码中不得通过打开 DEBUG 重新输出上述正文。需要问题复现时，使用受控的测试数据和独立环境；生产问题只依靠任务标识关联业务库中已有的授权数据。当前模型 SDK 未在流式响应中稳定提供 usage 时，Token 字段记为未知，不通过记录正文进行估算。

## 5. 密钥轮换与泄露处理

仓库历史中曾出现过开发数据库/Redis 密码、固定 JWT 密钥和微信 Secret。删除当前文件中的值不能清除 Git 历史，因此相关凭据应视为已泄露：立即在对应平台轮换，撤销旧值，再按需要清理 Git 历史。历史清理会改写提交记录，不属于模块一的自动操作范围。

轮换后验证：旧凭据失效、新凭据只存在于部署环境、应用可启动、日志搜索不到新旧凭据。不要在工单、截图或启动命令中粘贴真实值。
