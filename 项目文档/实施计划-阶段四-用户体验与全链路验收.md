# 阶段四：用户体验与全链路验收 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成地址三级联动、跨分类无限滚动搜索、个人资料与安全设置，并以 Chrome/WebKit 移动端 E2E、资金对账和旧旁路清理完成全链路验收。

**Architecture:** 商品搜索使用稳定游标和统一结果模型；行政区划使用本地版本化数据；头像通过受控上传；个人资料复用正式账号验证能力。最终验收以真实浏览器核心链路、数据库对账和异常事件清零为准。

**Tech Stack:** Spring Boot、MyBatis、Flyway、Vue 3、Pinia、Vitest、Vue Test Utils、Playwright、现有 OSS 上传能力。

**Spec:** `项目文档/用户端传统业务全链路优化设计说明.md`

## Global Constraints

- 搜索为单页连续列表，使用游标分批加载，不展示页码。
- 第一版不引入 Elasticsearch、拼音搜索、地图拖拽或自动定位。
- 头像只接受服务端受控上传，不接受用户填写外部 URL。
- 手机号换绑验证新旧手机号；密码修改使用当前密码或短信验证。
- 最终移除演示账号预填、默认密码注册、URL 支付成功判定和固定 0.01 元退款。
