# 阶段三：取消、退款、售后与通知 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付订单时间轴、直接取消、审核取消、整单售后、全额退款、退款失败重试、持久化通知和 WebSocket 补拉闭环。

**Architecture:** 订单状态、支付状态、退款状态和售后状态分表保存。业务事务写时间轴、通知和 Outbox；发布器异步推送 WebSocket。退款先冻结来源资金，成功后转给用户，失败沿用原退款单重试。

**Tech Stack:** Spring Boot、MyBatis、Flyway、MySQL/H2、WebSocket、JUnit 5、Vue 3、Pinia、Vitest、Playwright。

**Spec:** `项目文档/用户端传统业务全链路优化设计说明.md`

## Global Constraints

- 待付款直接取消；待接单取消自动全额退款；制作中和配送中必须审核。
- 已完成订单从实际送达时间起 24 小时内可申请整单全额售后。
- 同一订单只能有一个进行中的申请。
- 退款失败不得显示成功，不得重复冻结，不得超额退款。
- 通知保存 90 天；每日保留任务只清理超过 90 天的通知，不删除 Outbox 死信和订单时间轴。WebSocket 消息不是最终事实来源。
