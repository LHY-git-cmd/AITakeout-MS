# 饱饱助手可靠决策与推荐闭环实施报告

## 1. 完成结果

已完成“场景识别 → 结构化约束 → Java过滤排序 → 单一推荐结果 → 确定性文字解释”的可靠闭环，解决知识说明与推荐卡片互相矛盾的问题。

## 2. 主要改造

### 2.1 场景与契约

- 新增 `COMMON_COLD` 和 `SEASONAL_REGIONAL` 场景；
- 感冒、发烧、咳嗽、喉咙痛等映射到一般身体不适辅助；
- 入秋、秋天、时令和当季映射到地域时令场景；
- 感冒自动生成 `NO_ALCOHOL/NO_SPICY/NO_HIGH_OIL/NO_HIGH_SODIUM_PICKLED`；
- 杭州入秋生成 `CN-ZJ-HZ + AUTUMN`；
- 时令请求缺少地区时只追问，不执行推荐。

### 2.2 工具白名单

- 普通点餐仍可使用普通商品搜索；
- 健康和时令场景只暴露 `get_diet_profile` 与 `recommend_personalized_meals`；
- 编排层对越权调用返回 `TOOL_SCENE_DENIED`；
- 高风险医疗场景不暴露商品推荐工具。

### 2.3 菜品适配数据

新增版本化表 `dish_diet_adaptation_profile`，保存：

- 辣度、油量、盐分；
- 温热属性和易消化程度；
- 酒精、腌制食品和汤底属性；
- 模拟版本、验证状态和来源。

已导入24道菜的 `SIM-MENU-V1` 模拟适配数据，以及杭州地区7条模拟时令规则。

### 2.4 Java二次裁决

`COMMON_COLD` 在评分前排除：

- 酒精；
- 辣度达到阈值的菜；
- 高油菜品；
- 高盐或腌制菜品；
- 缺少适配数据的套餐。

通过硬过滤后，根据温热、清淡、易消化、较低油盐进行排序。Java同时返回推荐商品、被排除商品、原因码、场景和模拟数据提示。

### 2.5 单一结果与统一解释

- 同一 `task_id` 最多发布一个 `recommendation_cards`；
- 健康场景即使模型错误调用 `search_products`，也不会派生普通推荐卡片；
- 健康推荐完成后不再进行第二轮自由模型回答；
- 文字摘要直接由Java结果对象生成，因此不会添加未推荐商品或推荐已排除商品；
- 用户端可展开查看已排除商品和原因。

## 3. 验证结果

### 感冒真实接口

输入条件：`COMMON_COLD`。

最终前5项：

```text
鸡蛋汤、清蒸鲈鱼、清炒小油菜、清炒西兰花、蒜蓉娃娃菜
```

验证：

- 风险等级为 `L1`；
- 老坛酸菜鱼未进入推荐；
- 蜀味水煮草鱼未进入推荐；
- 金汤酸菜牛蛙未进入推荐；
- 雪花啤酒未进入推荐；
- 被排除商品带 `NO_SPICY/NO_HIGH_OIL/NO_ALCOHOL` 等原因码。

### 入秋真实接口

输入条件：`SEASONAL_REGIONAL + CN-ZJ-HZ + AUTUMN`。

杭州10月时令规则参与排序，清炒小油菜、蒜蓉娃娃菜、清炒西兰花和炝炒圆白菜均带 `SEASONAL_INGREDIENT` 原因。

## 4. 当前边界

- 适配和时令数据为开发模拟数据，生产默认不使用；
- 时令数据目前只提供杭州开发样例；
- 感冒场景属于一般饮食辅助，不宣称治疗；
- 高风险症状继续提示专业或急救处理；
- 慢病规则仍需审核发布后才能参与正式筛选。
