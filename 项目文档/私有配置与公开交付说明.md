# 私有配置与公开交付说明

## 本地启动和部署

私有配置优先级：脚本 `-EnvFile` 参数、`SKY_ENV_FILE` 环境变量、已有的项目 `.env`、当前用户 LocalApplicationData 下的 `metrics-backend/private-config/sky-take-out.env`。现有本机配置已移到最后一个位置，内容保持一致。

```powershell
# 只验证配置结构，不输出展开后的密码。
pwsh -File scripts/sky-compose.ps1 config --quiet

# 查看本地服务。
pwsh -File scripts/sky-compose.ps1 ps

# 本地 Java 示例（先构建 JAR）。参数数组避免 Java/Python 的开关被 PowerShell 解析。
& ./scripts/with-private-env.ps1 -Command java -CommandArguments @('-jar', 'sky-server/target/sky-server-1.0-SNAPSHOT.jar')

# 完整部署入口，自动使用相同私有配置。
pwsh -File scripts/deploy-clean.ps1
```

运行 Java 命令时选择 `sky-server` 模块或指定正确的 JAR；Python 命令在 `agent-service` 目录运行。对于独立 Python Agent，可把 `SKY_AGENT_ENV_FILE` 设置为专用项目外配置路径；进程环境变量优先级仍高于文件。`with-private-env.ps1` 支持普通 KEY=VALUE 及包裹值的引号，不执行 shell 表达式。

直接运行 `docker compose` 不会自动知道项目外配置的位置。请使用上述入口，或明确指定 `--env-file`。Docker 容器环境通过 Compose 注入；已有容器不会因为文件迁移自动重建。

## 密码与实时消息变更

- 登录表单不预填密码。新增员工必须填写独立初始密码，12至64位可打印 ASCII 字符，不含空格。使用密码管理器生成随机密码。
- 编辑员工资料不会修改密码。修改自己的密码时必须提供原密码，新密码使用相同规则。服务端只存 BCrypt 哈希，员工接口和对象日志不包含密码哈希。
- 现有账号密码不自动改变。旧弱密码需要账号持有人主动修改；修改密码不会立即撤销已签发的无状态 JWT。若确认令牌泄露，需安排 JWT 签名密钥轮换和重新登录。
- WebSocket URL 仅含会话标识。连接后的第一条消息为 `{"event":"authenticate","role":"admin或user","token":"当前访问令牌"}`；收到服务端 `connected` 后再发送订阅和心跳。
- 两个前端与 Java 后端需要配套发布。旧页面应刷新，代理不再接受 `?token=` 形式。未认证连接无法接收业务消息，10秒内未完成认证会关闭。
- 访问日志省略查询参数和客户端地址。Java/Python 应用日志遮盖常见凭据及个人号码。Nginx 错误日志仍属于私有运维数据，不应公开。
- 结算预览签名密钥必须设置 `CHECKOUT_PREVIEW_SECRET`，不再使用所有开发环境共享的默认值。

## 公开源码导出

```powershell
# 目标必须是项目外且尚不存在的目录。私有配置只用于扫描比对，不会被导出。
python scripts/export-public-source.py --output ../public-source --private-env $env:SKY_ENV_FILE
```

导出内容包括 Java、两个 Web 前端、Agent、Embedding 的固定构建文件、部署配置、测试源码和 Markdown 文档。其余顶层资料、小程序旧工程、私人笔记、Office 文件、截图目录、Git 历史、工作副本、依赖、模型、数据库、上传文件、日志和测试输出不在交付范围。

导出前扫描已知实际密钥、凭据格式、本机路径、敏感表的数据 INSERT 和前端环境字段。发现问题时只输出路径、行号和规则，不生成发布目录。`PUBLIC_SOURCE_MANIFEST.json` 记录交付文件哈希。媒体素材未做 OCR；扫描规则无法证明所有秘密都不存在，发布前仍需人工确认素材与业务文档。

`.gitignore` 只负责忽略规则，不能从已跟踪文件或历史提交中移除内容。本次处理不检查或修改 Git 状态。需要审查历史时，另行安排有授权的历史检查和清理。

## 待安排的凭据轮换

如果确认曾公开或不可信共享，需要更换：服务器管理面板密码、服务器及本地数据库密码、Redis 密码、管理员初始密码、LLM API Key、管理端和用户端 JWT 签名密钥、Agent 内部服务 Token、结算预览签名密钥。

这些凭据必须在对应服务端与调用方同步修改。仅修改本地文件不会更改数据库或供应商的实际凭据。JWT 轮换会使现有登录失效；内部服务 Token 轮换应同步 Java 与 Agent；结算签名密钥轮换后用户需重新获取结算报价。轮换后的旧私有备份也应按实际保留需求处理。
