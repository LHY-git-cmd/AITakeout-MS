# 阶段二：结算试算与配送 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付始终执行的配送校验、分段配送费、权威订单试算、预约时段和幂等下单，使前端不再提交或决定订单金额。

**Architecture:** `DeliveryMapGateway` 隔离模拟地图与百度地图，`CheckoutQuoteService` 统一核价、配送和时间计算。试算签名只检测用户确认内容是否变化，正式提交仍重新查询全部业务数据并保存订单快照。

**Tech Stack:** Spring Boot、MyBatis、Flyway、H2/MySQL、Java HTTP client、Vue 3、Pinia、Vitest、Playwright。

**Spec:** `项目文档/用户端传统业务全链路优化设计说明.md`

## Global Constraints

- 默认配送规则为 3000 米内 500 分、3001—5000 米 800 分、超过 5000 米拒绝。
- 未配置百度 AK 不得跳过校验；开发环境必须显式启用 `mock` 地图实现。
- 试算有效期 5 分钟，正式下单必须重新核价。
- 相同用户和幂等键只能创建一个订单。
- 商品、价格、联系人和地址必须保存订单快照。
