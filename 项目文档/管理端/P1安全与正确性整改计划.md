# P1 安全与正确性整改计划

## 1. 整改目标

本计划落实 2026-08-21 项目巡检中列出的 P1 建议，范围限定为：

1. 员工密码由无盐 MD5 迁移至 BCrypt。
2. 禁止在日志中输出 JWT，并规范认证失败日志。
3. 在每次请求结束时清理 `BaseContext` 中的 `ThreadLocal`。
4. 将 CORS 从任意来源调整为可配置白名单。
5. 为外部输入增加 Bean Validation，并统一返回参数错误。
6. 将订单状态变更改为带前置状态条件的原子更新，防止并发重复操作。

本次不处理 P0 支付金额、订单金额重算和微信回调验签，也不进行前端框架升级。

## 2. 技术选型声明

### 2.1 密码哈希

采用 Spring Security Crypto 的 `BCryptPasswordEncoder`，不引入完整 Spring Security 认证链。保留对现有 32 位 MD5 数据的临时兼容：旧密码验证成功后立即写回 BCrypt 哈希；新建员工及修改密码只生成 BCrypt。这样无需停机批量获取明文密码，也不会中断现有账号登录。

### 2.2 请求校验

采用 Jakarta Bean Validation 和 Spring Boot Validation Starter。约束定义在 DTO 或请求模型上，Controller 使用 `@Valid` / `@Validated` 触发校验，全局异常处理器输出稳定的业务错误结构。

### 2.3 并发状态控制

订单状态流转采用数据库条件更新：`UPDATE ... WHERE id = ? AND status = ?`。服务层根据影响行数判断状态是否已被其他请求修改。该方案不额外引入分布式锁，单数据库与多实例部署下均能保证单次状态转换的原子性。

## 3. 三项关键改进建议

1. BCrypt 的 MD5 兼容逻辑应设下线窗口；迁移完成后删除 MD5 验证分支，避免长期保留弱算法。
2. CORS 白名单应分别配置开发和生产值，生产环境不得使用 `*`；凭据模式下只允许明确来源。
3. 所有订单入口统一使用状态条件更新，包括管理端操作、用户取消、支付成功和定时任务，避免只修复部分接口后留下旁路。

## 4. 实施模块

### 模块一：密码与认证上下文

- 增加 BCrypt 依赖与编码器 Bean。
- 调整员工登录、新增员工和修改密码逻辑。
- 兼容验证旧 MD5 哈希，并在成功登录后自动升级。
- 删除管理员端和用户端 JWT 明文日志。
- 在两个 JWT 拦截器的 `afterCompletion` 中清理 `BaseContext`。
- 增加密码迁移、错误密码和上下文清理测试。

验收标准：新密码不再生成 MD5；旧账号可以登录且哈希会升级；日志不包含令牌；请求完成后线程上下文为空。

### 模块二：CORS 与输入校验

- 增加 `sky.cors.allowed-origins` 配置，默认仅允许本地开发地址。
- 使用配置属性绑定白名单，移除 `allowedOriginPatterns("*")`。
- 引入 Bean Validation。
- 为登录、员工、分类、菜品、套餐、购物车、地址、订单等外部输入增加非空、长度、数值范围和格式约束。
- 在 Controller 请求体使用 `@Valid`，查询参数和路径参数使用 `@Validated`。
- 全局处理 `MethodArgumentNotValidException` 和约束校验异常，避免将内部异常信息返回客户端。
- 增加关键接口参数校验测试。

验收标准：非法请求在进入业务层前被拒绝；响应仍符合现有 `Result` 结构；生产配置可声明多个明确来源。

### 模块三：订单状态并发控制

- 在 `OrderMapper` 增加按订单 ID、期望状态和目标状态更新的方法。
- 改造接单、拒单、商家取消、用户取消、派送、完成和支付成功流程。
- 定时任务使用带状态条件的更新，避免覆盖并发业务操作。
- 对退款类流程保留事务边界，并明确外部退款成功与数据库状态更新失败的补偿风险。
- 增加重复请求和并发状态变化单元测试。

验收标准：两个并发请求只有一个状态转换成功；失败方收到明确的订单状态错误；不会覆盖已变化的订单状态。

### 模块四：验证与整改报告

- 执行 Maven 编译和测试。
- 检索 JWT 日志、MD5 新写入、开放 CORS 和未清理 ThreadLocal 等残留。
- 检查 Git 差异，确保不覆盖既有用户改动。
- 生成 `项目文档/P1安全与正确性整改报告.md`，记录变更、测试结果、未解决风险和后续建议。

## 5. 执行顺序

1. 模块一：密码与认证上下文。
2. 模块二：CORS 与输入校验。
3. 模块三：订单状态并发控制。
4. 模块四：全量验证与整改报告。

按照项目协作要求，每完成一个模块先展示当前产出，再确认是否继续下一模块或调整方向。

## 6. 风险与回滚

- 密码字段长度必须至少容纳 60 字符的 BCrypt 哈希；实施前先核对数据库定义。若长度不足，需要提供数据库迁移脚本。
- 输入校验可能暴露前端此前发送的空值或非标准字段；测试时需覆盖管理端与用户端主要写操作。
- 条件更新会把此前静默覆盖转为显式状态错误，前端应能展示现有业务错误消息。
- 本次工作树已有未提交改动，所有修改均基于现状增量完成，不回退或格式化无关文件。
