## 3. 具体改动及作用

### 管理端

- 升级 Vue 至 `2.7.16` 最终版，并将 Vue CLI、Webpack、TypeScript、Axios、Element UI、ECharts、Jest 统一到可在 Node 24 上工作的版本。
- 删除 `fibers`、Webpack 4、Babel 7 bridge、PWA/Cypress 未使用配置及未引用的 service worker 文件，降低原生安装失败和维护面。
- 增加缺失的 ESLint/Jest peer 依赖，固定 `@types/node@18.19.70`，并写入 `packageManager: yarn@1.22.22`，保证安装工具一致。
- 将 `path` 浏览器兼容导入改为 `path-browserify`；按 Cookies 3 字符串契约序列化对象；修复装饰器属性初始化顺序。
- 移除不兼容的 CSS Module 导出用法，使用显式主题常量，消除构建期变量导出告警。
- Breadcrumb 单测改为等待 `router.push` 和 `$nextTick`，并修正路由测试夹具。

### 用户端

- 将 17 个 Vue 文件中的 `lucide-vue-next` 导入迁移到官方替代包 `@lucide/vue`，保留组件名称和交互行为，消除上游废弃包告警。

## 5. 残余风险与后续建议

1. Vue 2.7 仍处于 EOL，审计中的低危 ReDoS 只能通过后续 Vue 3 迁移根治；建议单独立项完成 Vue 3 + Vue Router 4/Vuex 替代方案迁移。
2. `vue-svgicon` 同时承担运行时图标和 SVG 生成，传递的 `svgo@1.3.2`、`nth-check`、`yargs-parser` 仍有高/中危项；不建议直接强制 resolutions，建议迁移到现代图标组件与独立 SVG 构建链。
3. Vue CLI 5、webpack-dev-server 4、Jest 27 的部分漏洞来自开发/构建链；应限制开发服务器暴露范围，并在 Vue 3/Vite 迁移中一并淘汰。
4. 管理端 vendor 约 2.43 MiB、CSS 约 373 KiB，登录图约 1.78 MiB，仍会影响首屏下载。建议后续按路由拆分 ECharts/Element UI、压缩登录图为 WebP/AVIF，并继续检查大于 244 KiB 的菜品图片。
5. 管理端 lint 当前仍有历史质量债务：1374 problems（777 errors、597 warnings），本轮未做全量自动格式化，避免引入无关代码变更；建议分模块治理并设置增量 lint 门禁。
