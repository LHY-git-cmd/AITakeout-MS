# 模块二：三个应用服务容器化

## 1. 实施范围与技术选型

本模块只完成 `sky-server`、`sky-agent`、`sky-embedding` 的独立镜像构建契约，不创建 Compose，不编排 MySQL、Redis 或 Qdrant。

- `sky-server`：Maven + Java 21 多阶段构建，运行层只包含 JRE、curl 和应用 JAR。
- `sky-agent`：Python 3.11 单进程，直接依赖固定版本；任务 SQLite、知识索引 SQLite 和知识源统一位于 `/app/data`。
- `sky-embedding`：Python 3.11 CPU 镜像，镜像不包含模型；模型必须挂载到 `/models/bge-m3`。
- 三个运行镜像均使用 UID/GID `10001` 的非 root 用户。
- Java 使用 Actuator readiness；Agent 和 Embedding 分别暴露 `/health/live` 与 `/health/ready`。
- Java 和 Python 容器收到 SIGTERM 后最多等待 30 秒进行优雅关闭。

## 2. 构建命令

在 `sky-take-out` 根目录执行：

```powershell
docker build -t sky-server:module2 .
docker build -t sky-agent:module2 ./sky-agent
docker build -t sky-embedding:module2 ./sky-embedding
```

构建上下文中的 `.env`、Git 元数据、测试缓存、运行数据、知识文件和模型目录均由 `.dockerignore` 排除。注意：当前 Windows 工作区的 `sky-agent` 是指向 `E:\Pyhon\FastAPIProject1` 的 Junction，并且被主仓库 `.git/info/exclude` 排除；发布前必须保证 Agent 独立仓库的 Docker 改动已提交并能被 CI 获取。

## 3. 独立运行约定

### sky-server

必须注入模块一列出的数据库、Redis、JWT、Agent 和 LLM 配置。JVM 参数通过 `JAVA_TOOL_OPTIONS` 覆盖，例如：

```powershell
docker run --rm --name sky-server -p 8080:8080 `
  --env-file .env `
  -e "JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75.0 -Xms256m" `
  sky-server:module2
```

readiness：`GET /actuator/health/readiness`。

### sky-agent

必须把 `/app/data` 挂载到可写卷；容器只有一个 Uvicorn worker，不能直接增加 worker 数量：

```powershell
docker volume create sky-agent-data
docker run --rm --name sky-agent -p 8000:8000 `
  --env-file .env `
  -v sky-agent-data:/app/data `
  sky-agent:module2
```

liveness：`GET /health/live`；readiness：`GET /health/ready`，响应会分别标明 Qdrant 与 Embedding 是否可用。

### sky-embedding

模型只能以只读卷提供。镜像不会下载模型，也不会在构建时复制模型：

```powershell
docker run --rm --name sky-embedding -p 8001:8001 `
  -v "E:\Pyhon\sky-embedding\models\bge-m3:/models/bge-m3:ro" `
  sky-embedding:module2
```

该路径对应当前工作区的实际模型目录。也可以在 `.env` 中设置 `BGE_MODEL_HOST_PATH=E:/Pyhon/sky-embedding/models/bge-m3`，由 Compose 自动挂载；目录内应直接包含 `pytorch_model.bin`、`config.json` 等模型文件。

liveness：`GET /health/live`。readiness：`GET /health/ready`，模型加载中或失败时返回 HTTP 503；`GET /health` 返回 `starting`、`healthy` 或 `failed`。

`model-manifest.example.json` 记录当前 BGE-M3 revision 和关键文件 SHA-256。部署前应对挂载目录执行校验；不匹配时不得启动服务。模型路径必须是本地目录，因此 `BGEM3FlagModel` 不会根据模型名静默下载远端权重。

## 4. 验收步骤

镜像构建后检查运行用户、挂载点和健康检查：

```powershell
$imageNames = 'sky-server:module2', 'sky-agent:module2', 'sky-embedding:module2'
foreach ($imageName in $imageNames) {
  $image = (docker image inspect $imageName | ConvertFrom-Json)[0]
  $volumes = if ($null -eq $image.Config.Volumes) {
    '{}'
  } else {
    $image.Config.Volumes | ConvertTo-Json -Compress
  }
  [PSCustomObject]@{
    Image   = $imageName
    User    = $image.Config.User
    Volumes = $volumes
    Health  = $image.Config.Healthcheck.Test -join ' '
  }
}
```

预期：三个 `user` 均为 `10001:10001`；Agent 声明 `/app/data`；Embedding 声明 `/models`；三者均有 healthcheck。

验证 Embedding 镜像不含权重：

```powershell
docker run --rm --entrypoint python sky-embedding:module2 -c `
  "from pathlib import Path; assert not Path('/models/bge-m3/pytorch_model.bin').exists()"
```

持久化验收应向 Agent 创建任务/索引数据，删除容器后使用同一 `sky-agent-data` 卷重建，再确认状态仍可读取。完整依赖联调和自动创建卷属于模块三。
