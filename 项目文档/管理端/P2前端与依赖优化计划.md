# P2 前端与依赖优化计划

## 1. 目标与边界

本轮处理两个 Web 前端的构建可用性、依赖安全和质量门禁。管理端执行渐进式工具链升级，用户端保持现有 Vue 3 / Vite 架构，仅处理必要补丁。页面设计、业务流程、REST 接口和 Vue 3 全量迁移不在本轮范围内。

## 2. 基线问题

- 管理端为 Vue 2.6、Vue CLI 3、Webpack 4 和 TypeScript 3.6。
- 管理端显式依赖已废弃的 `fibers`，Node 24 下缺少可用原生二进制。
- Webpack 4 使用旧 OpenSSL 哈希算法，Node 24 构建报 `ERR_OSSL_EVP_UNSUPPORTED`。
- 管理端 Axios 0.19、Element UI 2.12 等运行时依赖长期未更新。
- 用户端为 Vue 3.5、Vite 7，基线构建成功且官方 npm 审计为 0 漏洞。

## 3. 技术选型声明

1. 管理端升级到 Vue 2 最终版 2.7.16 和 Vue CLI 5 / Webpack 5，先恢复现代 Node 构建能力；Vue 3 重写另立迁移项目。
2. 删除 `fibers`、Webpack 4 和旧 Babel 桥接，使用 Dart Sass 与 Webpack 5，减少原生安装失败和旧运行时依赖。
3. 以干净安装、类型检查、单元测试、生产构建和官方 npm 审计作为验收，不以“安装成功”替代可运行验证。

## 4. 执行模块

1. 记录双端 Node、构建、依赖和审计基线。
2. 升级管理端核心框架、构建、样式、测试和代码检查依赖。
3. 迁移开发服务器配置并修复依赖 API/类型兼容问题。
4. 更新用户端安全补丁，不跨 Vite、Pinia、Router 主版本。
5. 执行双端干净安装、类型检查、测试、生产构建和官方审计。
6. 生成前后现象、原因、作用、数据和风险整改报告。

## 5. 风险控制

- Vue 2 已停止维护；本轮升级到最终版只能降低现状风险，不能替代后续 Vue 3 迁移。
- Axios 1.x 的类型和拦截器契约有变化，需要编译和登录/API 冒烟验证。
- 锁文件将由当前 npm 重新生成，必须使用 `npm ci` 验证可重复安装。
- 保留工作区中与本轮无关的用户文件和改动。
