# 第二阶段 AI 工具调用实施报告

> **当前状态（2026-09-17）**：本文记录的工具定义、确认协议、权限边界和自动化测试已纳入管理端 Agent 第一版交付。工具专项评测与 Compose 端到端验收由模块六、模块七及《管理端 Agent 第一版最终实施报告》统一引用；本文不再单独作为上线结论。

## 1. 实施结果

第二阶段已按《第二阶段 Python AI 工具调用方案》完成第 1–8 模块。最终职责边界为：Python 负责工具选择和多步编排，Java 负责权威身份、最终鉴权、原子业务、确认凭证、幂等、事务、脱敏和审计。

## 2. 已交付能力

- 管理员角色及逐项权限模型；普通管理员禁止员工、知识库 CUD。
- 18 个 Python Pydantic 工具定义，其中 14 个只读、4 个需要确认的写工具。
- OpenAI 兼容 tools Schema、多轮工具循环、工具轮次/并发上限和 Java HTTP 客户端。
- 员工、知识库、订单、菜品、套餐、店铺及经营报表原子查询。
- Java AI 专用白名单 VO，密码不返回，个人信息脱敏。
- 写操作 `prepare → 用户 confirm/reject → execute-confirmed` 协议。
- 参数哈希、对象版本、一次性状态转换和本人确认约束。
- `tool_start`、`tool_result`、`tool_confirmation_required`、等待保活等 SSE 事件。
- 管理端确认卡片，提供清晰摘要、拒绝和确认执行状态。
- 工具审计与统一错误信封。

## 3. 安全边界

- Python 收到的角色只是工具可见性快照；Java 每次依据 `task_id → employee_id → 当前数据库角色` 裁决。
- 内部原子接口由服务间令牌保护，Python 不访问业务数据库。
- 写凭证绑定任务、管理员、工具调用、参数和业务对象版本，过期或重复消费均拒绝。
- 工具与 RAG 内容按不可信数据回填模型，系统提示明确禁止服从其中指令。
- Java 再次拒绝未知 operation、未知参数、越界分页、超长日期范围和不完整写参数。

## 4. 配置与迁移

- `AGENT_INTERNAL_SERVICE_TOKEN`：至少 32 字符，Java/Python 必须一致。
- `TOOL_CONFIRMATION_TIMEOUT_SECONDS`：确认有效期，默认 300 秒。
- 数据库依次应用 `V20260913_01`、`V20260913_02`、`V20260913_03`。

## 5. 验证结果

- Java：61 项测试通过。
- Python：48 项测试通过，1 项依赖真实 Qdrant/Embedding 的可选 E2E 测试跳过。
- 管理端：生产构建通过；仅保留项目原有 Sass 废弃与包体积警告。
- Docker Compose 配置解析通过。
- Git diff 空白检查通过。

## 6. 第一版收口后的上线条件

部署前需配置真实服务令牌并应用数据库迁移。模块一至模块七已完成验收；后续上线、回滚和残余风险统一按《管理端 Agent 第一版最终实施报告》及《模块七-部署运维与故障处理》执行。第一版仍限定为单机 Compose、单 Agent worker、非高可用部署。
