## 3. 整改内容

### 3.1 密码与认证上下文

1. 引入 `spring-security-crypto`，使用 `BCryptPasswordEncoder` 生成员工密码哈希。
2. 新建员工的默认密码不再写入 MD5。
3. 保留临时兼容迁移：识别数据库中的 32 位 MD5；旧密码验证成功且账号可用时，立即更新为 BCrypt。
4. 已确认部署 SQL 中 `employee.password` 为 `varchar(64)`，可容纳 60 字符 BCrypt，无需修改表结构。
5. 管理端登录日志改为只记录用户名，不再通过 DTO 输出明文密码。
6. 删除管理员端和用户端 JWT 令牌明文日志，同时删除调试线程输出。
7. 两个 JWT 拦截器均在 `afterCompletion` 中调用 `BaseContext.removeCurrentId()`，防止线程池复用导致身份残留。
8. 微信登录日志不再记录一次性登录凭证 `code`。

主要实现文件：

- `sky-server/src/main/java/com/sky/config/PasswordConfiguration.java`
- `sky-server/src/main/java/com/sky/service/impl/EmployeeServiceImpl.java`
- `sky-server/src/main/java/com/sky/interceptor/JwtTokenAdminInterceptor.java`
- `sky-server/src/main/java/com/sky/interceptor/JwtTokenUserInterceptor.java`

### 3.2 CORS 与输入校验

1. CORS 从任意来源调整为明确来源列表。
2. 新增 `sky.cors.allowed-origins`，可通过环境变量 `CORS_ALLOWED_ORIGINS` 覆盖。
3. 默认仅允许 `http://localhost:9528` 和 `http://localhost:8081`。
4. 引入 Jakarta Bean Validation，Controller 使用 `@Valid` 在业务方法执行前校验请求。
5. 已覆盖员工、分类、菜品、套餐、购物车、地址、订单、微信登录和 Web 演示登录等写请求。
6. 已覆盖分页页码及每页数量，单页最大限制为 100。
7. 购物车增加“菜品 ID 和套餐 ID 必须且只能填写一个”的对象级约束。
8. 全局异常处理器增加参数校验异常处理，继续使用现有 `Result` 响应结构，不向客户端返回内部异常堆栈。

部署要求：生产环境必须设置实际允许的来源，例如：

```text
CORS_ALLOWED_ORIGINS=https://admin.example.com,https://user.example.com
```

不得将生产值设置为 `*`。

### 3.3 订单状态并发控制

1. 新增按 `订单 ID + 期望订单状态` 执行的条件更新。
2. 新增按 `订单 ID + 期望订单状态 + 期望支付状态` 执行的支付条件更新。
3. 接单、拒单、用户取消、商家取消、派送、完成和模拟支付均检查数据库实际影响行数。
4. 微信支付成功回调使用支付条件更新；重复通知不会重复修改状态或重复推送来单提醒。
5. 两个订单定时任务只通知实际完成状态转换的订单。
6. 条件更新影响行数不是 1 时，业务层返回订单状态错误，不再覆盖其他并发请求已完成的修改。
7. 已支付订单取消时，先在当前事务中取得状态转换资格，再调用退款，减少并发重复退款风险；退款异常会触发数据库事务回滚。

主要实现文件：

- `sky-server/src/main/java/com/sky/mapper/OrderMapper.java`
- `sky-server/src/main/resources/mapper/OrderMapper.xml`
- `sky-server/src/main/java/com/sky/service/impl/OrderServiceImpl.java`
- `sky-server/src/main/java/com/sky/task/OrderTask.java`

## 5. 兼容性说明

1. 现有 MD5 员工账号无需批量重置密码，首次成功登录后自动迁移。
2. 已经是 BCrypt 的账号不会重复编码。
3. 参数错误仍返回 `code = 0` 和 `msg`，前端无需修改基础响应解析。
4. CORS 默认值适用于本地开发；生产环境升级后必须同步配置允许来源。
5. 订单并发冲突将由此前的静默覆盖变为明确的“订单状态错误”，这是预期行为。

## 6. 尚存风险与后续事项

1. MD5 兼容分支仍属于弱算法代码。建议统计所有员工密码均迁移后删除该分支，并设置明确下线日期。
2. 本次订单并发测试为服务层单元测试，尚未使用真实 MySQL 执行多线程集成测试；上线前建议补充数据库级并发验证。
3. 外部微信退款与本地数据库事务无法形成分布式原子事务。若退款成功后数据库提交失败，仍需要退款单状态查询或补偿任务。
4. P0 中的微信支付回调签名、商户号/AppID/金额核验以及密钥迁移仍需单独完成。
5. 生产环境的 OpenAPI/Swagger 端点仍默认开启，本次不在 P1 约定范围内，建议后续按环境关闭。
