# 第二阶段 AI 工具调用需求说明

## 1. 目标

在现有管理端 AI 对话与 RAG 能力上增加受控业务工具调用，使管理员可以用自然语言查询业务数据，并在本人明确确认后修改允许范围内的业务状态。

## 2. 系统职责

- Python Agent：工具 Schema、角色可见工具集、LLM 工具选择、多轮编排、确认等待及工具结果回填。
- Java：JWT 身份入口、任务与员工绑定、数据库当前角色复核、业务权限、参数复核、事务、幂等、审计、脱敏及原子业务执行。
- Python 不直连业务数据库，不把模型判断当作最终授权依据。

## 3. 角色与权限

### 3.1 超级管理员

`SUPER_ADMIN` 拥有全部已注册管理权限，但仍必须遵守敏感字段过滤、写操作确认、业务规则、审计和幂等约束。

### 3.2 普通管理员

- 员工、知识库：允许读取，禁止新增、修改和删除。
- 订单、菜品、套餐、经营数据：允许读取。
- 订单状态、菜品、套餐、店铺状态：允许修改，但每次必须由发起任务的管理员确认。
- 所有工具逐项校验权限，不允许仅按页面、会话或模型提示词进行粗粒度授权。

## 4. 工具范围

只读工具共 14 项：员工列表/详情、知识库列表/文档列表、订单列表/详情/统计、菜品列表/详情、套餐列表/详情、店铺状态、经营概览、经营报表。

写工具共 4 项：订单状态修改、菜品修改、套餐修改、店铺状态修改。

明确禁止员工和知识库 CUD 工具进入普通管理员工具集或 Java 可执行映射。

## 5. 安全要求

- Java 每次调用均使用 `task_id` 找回 `employee_id`，再读取数据库当前角色；不信任 Python 传入角色快照。
- 停用、删除或权限已变化的管理员立即失去执行权限。
- 密码永不进入工具结果；手机号、身份证号、姓名和订单地址等由 Java 专用 VO 脱敏。
- Java 对 Python 已校验参数进行二次校验，拒绝未知字段、越界分页、异常日期范围和缺失必填项。
- 工具结果以不可信业务数据回填模型，其中出现的指令不得改变系统行为。
- 内部接口必须携带至少 32 字符的服务间凭证。

## 6. 写操作确认

1. Python 根据模型选择向 Java 请求准备写操作。
2. Java 生成一次性 `confirmation_id`，保存参数哈希、业务对象版本、操作摘要、管理员和过期时间。
3. 前端展示明确的操作摘要，并提供“拒绝”和“确认执行”按钮。
4. 只有原任务管理员可以确认；确认时再次检查数据库当前权限。
5. Python 得知已确认后请求执行；Java 再次检查权限、参数哈希、对象版本和凭证状态。
6. 凭证只能成功消费一次；拒绝、过期、参数变化或对象版本变化均不得执行。

## 7. 审计与错误语义

审计至少记录请求、任务、工具调用、管理员、角色、操作、所需权限、参数摘要、状态、错误码、耗时、追踪 ID 和时间。审计不得记录密码、完整证件号码或完整业务请求正文。

统一状态包括：`success`、`rejected`、`failed`、`confirmation_required`、`expired`。主要错误包括权限拒绝、未知工具、参数错误、确认缺失/过期/已使用、业务对象版本冲突和上游超时。

## 8. SSE 事件

工具链路使用 `tool_start`、`tool_result`、`tool_confirmation_required` 和 `tool_waiting_confirmation` 事件；所有事件携带 `task_id`、`trace_id`、`seq_no`，工具事件同时携带 `tool_call_id`。Java 先幂等持久化再推送前端，支持断线续传。

## 9. 验收标准

- 14 个只读工具可通过自然语言选择并返回 Java 脱敏结果。
- 4 个写工具未经本人确认绝不执行，重复确认不会重复修改。
- 普通管理员无法通过提示注入、伪造角色、直接调用内部接口或篡改参数获得员工/知识库写能力。
- Java、Python 和管理端构建测试通过；权限、参数、超时、幂等、脱敏、确认与注入边界均有自动化验证。
