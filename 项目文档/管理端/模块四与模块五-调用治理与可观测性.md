# 模块四与模块五：调用治理与可观测性

## 交付边界

模块四负责 LLM Gateway、错误分类、有限重试、分层超时、取消、并发与排队、模型白名单和可选降级。模块五在同一调用边界采集日志、指标和追踪信息，并补充跨服务监控、告警、数据保留及备份恢复。

## 关键配置

生产环境必须显式设置 `LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_ALLOWED_MODELS` 和 `LLM_API_KEY`。降级模型只有同时设置 `LLM_FALLBACK_MODEL` 并加入白名单才会生效。认证失败、模型不存在、内容拦截和无效参数不会降级。

连接、首 Token 和总超时分别由 `LLM_CONNECT_TIMEOUT_SECONDS`、`LLM_FIRST_TOKEN_TIMEOUT_SECONDS`、`LLM_TOTAL_TIMEOUT_SECONDS` 控制。最大运行数和排队数分别由 `LLM_MAX_CONCURRENCY`、`LLM_MAX_QUEUE_SIZE` 控制。

成本估算使用供应商公开价格配置 `LLM_INPUT_COST_PER_MILLION` 和 `LLM_OUTPUT_COST_PER_MILLION`；未配置价格时成本保持为零，不伪造数据。

## 错误语义

稳定错误类型包括 `AUTH_FAILED`、`MODEL_NOT_FOUND`、`RATE_LIMITED`、`TIMEOUT`、`UPSTREAM_5XX`、`UPSTREAM_UNAVAILABLE`、`CONTENT_BLOCKED`、`INVALID_REQUEST`、`CAPACITY_EXCEEDED`、`CANCELLED` 和 `UNKNOWN`。流式请求只有在尚未输出内容时才能重试或降级。

## 指标与追踪

- Java：`/actuator/prometheus`
- Agent：`/metrics`
- Embedding：`/metrics`
- Qdrant：`/metrics`

`X-Trace-ID` 从 Java HTTP 入口建立并通过 Agent 请求、SSE 事件、Embedding 与 Qdrant 请求传播。Agent 对下游请求同时传播 `X-Task-ID` 和 `X-Session-ID`，使业务任务可在 Java、Agent、Embedding 和 LLM 日志间关联。日志不得记录 API Key、完整提示词、历史对话或知识正文。

启动可选观测组件：

```powershell
$env:GRAFANA_ADMIN_PASSWORD = '<strong-password>'
docker compose --profile observability up -d prometheus grafana node-exporter
```

Docker Desktop/Windows 不支持 node-exporter 的宿主机根目录 `rslave` 传播挂载，因此在本项目 Compose 中 node-exporter 默认不挂载 `/:/host`；Windows 上可以启动观测组件，但不提供宿主机文件系统指标。Linux 部署如需磁盘告警，请在 Compose override 文件中为 node-exporter 加回 `/:/host:ro,rslave` 和 `--path.rootfs=/host`。

Prometheus 默认监听 `9090`，Grafana 默认监听 `3000`。告警规则覆盖服务下线、连续 LLM 失败、HTTP 5xx 错误率升高、任务积压、首 Token 延迟、Embedding 未就绪和磁盘不足。生产环境需要在 Prometheus 中配置 Alertmanager 接收端。

## 数据保留

- Compose 容器日志：单文件 10 MB，保留 3 个文件。
- Prometheus：默认保留 15 天，可通过 `PROMETHEUS_RETENTION` 调整。
- Java 对话数据：沿用 `sky.ai.retention-days`，默认 90 天；生产部署必须配置相应清理任务。
- LLM 进程内指标在 Agent 重启后清零；长期和按天统计以 Prometheus 为准。

## 备份与恢复

执行备份：

```powershell
.\scripts\backup-ai-runtime.ps1 -BackupDirectory 'D:\sky-backups'
```

备份包含 MySQL 一致性导出、下载到备份目录的 Qdrant 集合快照、Agent 数据卷归档和 SHA-256 校验文件。

恢复前必须停止 `sky-server` 和 `sky-agent` 写入，并在隔离环境演练：

1. 使用 `scripts/verify-backup.ps1` 校验结构化的 `SHA256SUMS.json`；`SHA256SUMS.txt` 供人工或其他工具使用。
2. 向空 MySQL 实例导入 `mysql.sql`，启动 Flyway 并验证版本表。
3. 使用 Qdrant snapshot recovery API 恢复每个集合。
4. 将 `agent-data.tar.gz` 解压到空 Agent 数据卷。
5. 启动 Agent 和 Java，检查健康端点、任务状态、历史消息及一次带引用的 RAG 请求。

禁止直接覆盖正在运行的生产数据卷。备份恢复演练应记录日期、备份标识、恢复耗时和验证结果。
