# 管理端 Agent 添加菜品工具实施计划书

日期：2026-10-07

## 一、需求与边界

为管理端 Agent 增加添加菜品能力，复用现有 Java 业务服务与操作确认机制。

- 管理员仅说“帮我添加一些菜品”，且没有具体要求时，先询问是否生成测试数据。
- 回答“是”：生成恰好三道测试菜品，查询已有菜品分类并使用真实分类 ID；无可用分类时提示管理员先创建或提供分类，不自动建分类。
- 回答“不是”：说明需要具体信息，列出缺失字段；不擅自把正式菜品信息补成测试数据。
- 管理员直接提供具体信息时，校验并补问必要字段，信息完整后进入添加流程。
- 测试菜品默认停售，营养来源标记为模拟，保留待审核状态，不自动审核或发布。
- 图片暂时允许缺省，保存后提示管理员自行上传；不生成或下载图片。
- 生成完成后，通过现有确认卡片展示三道菜品的信息，管理员确认后才写入数据库。
- 此次只增加管理端能力，不把新增工具开放给用户端，不新增删除、分类创建或营养审核工具。

## 二、技术选型声明与三项关键改进

沿用 Python Agent 工具定义、Java 内部工具接口、MyBatis 与 Spring 事务，以及管理端现有确认卡片。无需引入新的模型供应商、数据库或框架。

1. 对话引导与数据校验分层：Agent 负责识别测试意图和生成候选内容，Java 负责权限、分类、价格、营养及过敏原结构校验。
2. 复用确认和审计机制：新增写操作接入现有准备、确认、执行链路，处理确认重复提交和执行重试，避免重复创建菜品。
3. 整批事务保存：菜品、口味、营养、食材、过敏原作为一个批次保存，任何一道失败则整批回滚；模拟数据不自动变为已审核数据。

## 三、数据与交互规则

“类型”按已确认选项解释为菜品分类，不包含套餐。

测试生成包含：名称、售价（元，最多两位小数）、真实分类、描述、主要食材、可选口味、每份重量、热量、蛋白质、脂肪、碳水、膳食纤维、糖、钠，以及过敏原声明。过敏原使用既有编码和声明状态，未知信息明确标记未知；以上均为模拟数据，不作为真实配方保证。

营养口径使用现有接口的“每份”口径，重量单位 g，能量 kcal，钠 mg。来源说明注明 Agent 生成的测试数据。

正式菜品流程要求管理员提供名称、分类和价格；食材、过敏原、营养按实际提供的信息保存，不编造缺失值或擅自作出无过敏原声明。图片可后续上传。

确认卡片展示名称、分类名称、价格、描述、食材、过敏原、营养数据、停售状态及图片待上传提示。确认前不落库，取消或超时不创建记录。确认后返回创建的菜品 ID 和结果；同一确认记录重复执行不重复创建。

图片缺省支持优先限定在新增工具的专用数据入口，避免改变现有手工新增表单的必填规则。

## 四、实施模块

### 模块一：Java 添加能力与确认链路

- 新增专用工具入参及批量添加业务入口，复用现有菜品和营养服务。
- 为新增操作接入管理端菜品写权限、准备确认、执行、审计和幂等结果。
- 支持空图片、分类有效性校验、重复名称冲突处理和整批事务回滚。
- 营养数据保持待审核状态，测试来源由服务端约束。
- 先添加有意义的失败测试，再实现功能；展示后端产出和测试统计。

### 模块二：Python 工具与对话引导

- 新增管理端分类查询能力及添加菜品工具定义，接入既有工具目录。
- 增加测试数据询问、三道候选生成、正式资料缺失追问等对话规则。
- 校验批次大小、分类 ID、价格和嵌套营养/过敏原参数；测试批次必须为三道。
- 验证工具可见性、参数约束、确认调用和上下文对话衔接；展示产出与测试统计。

### 模块三：确认展示与联调验收

- 在现有确认卡片中补齐新增菜品摘要和详细预览，复用确认/取消按钮。
- 验证无分类、拒绝测试、缺资料、确认、取消、超时及重复执行流程。
- 执行必要的 Java、Python 和管理端测试/构建，不向真实数据库写入联调测试菜品。
- 输出最终实施报告及手工验收步骤。

按照用户提供的 AGENTS.md，每个模块完成后展示当前产出，并询问：“是否继续下一模块？还是需要调整当前方向？”得到答复后继续。

## 五、验收标准

1. 无具体要求的添加意图先询问是否测试，不直接生成或保存。
2. 明确同意测试后生成三道内容完整的候选；未同意时不推定测试意图。
3. 无可用分类时不会提交不存在的分类 ID，也不会自动创建分类。
4. 确认卡片能核对三道菜品及营养、过敏原，确认后才创建记录。
5. 测试菜品停售、允许无图片、营养来源为模拟且待审核，后续可以手工维护。
6. 缺少正式菜品信息时准确追问，不编造业务事实。
7. 未授权调用、非法参数、取消、超时、重复执行和批次失败均有相应验证。
8. 失败日志只读取对应摘要/报告；Maven 输出写入日志，成功仅汇报最终测试统计。

## 六、交付物

Java 和 Python 工具实现、必要的确认预览调整、相关自动测试、手工验收步骤，以及最终实施报告。此计划阶段不执行部署、推送或真实菜品创建。
