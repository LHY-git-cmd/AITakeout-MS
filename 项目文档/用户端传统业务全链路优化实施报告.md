# 用户端传统业务全链路优化实施报告

## 1. 实施范围

本轮按四个阶段完成普通手机浏览器用户从正式账号、点餐、权威试算、下单、模拟支付、支付查询，到订单查询、取消/售后、全额退款、余额流水和通知的完整闭环。阶段四补齐跨分类搜索、地址三级联动、个人资料与安全设置，并完成 Chrome/WebKit 移动端验收和旧旁路清理。

## 2. 阶段四交付

### 2.1 商品搜索

- 菜品与套餐使用统一结果模型，按相关性、商品类型、ID 稳定排序。
- 使用 HMAC 签名游标，默认每批 20 条、最大 50 条。
- 前端保持单页连续列表，通过 `IntersectionObserver` 滑动加载，不展示页码。
- 下一批失败保留已有结果并提供重试；重复触发合并为一次请求。
- 登录用户保留最多 20 条去重搜索历史，返回点餐页恢复关键词、结果、游标和滚动位置。
- 数据迁移：`V20260922_01__add_user_search_history.sql`。

### 2.2 地址三级联动

- 使用固定版本 `area-data@5.0.6` 的本地区划数据，不依赖百度地图获取省市区。
- 原生 `select` 完成省、市、区县联动，上级变化时清空下级选择。
- 同时提交区划代码和名称，直辖市名称统一规范化。
- 地址保存后仍由模拟地图或百度地图适配器完成配送范围校验，并展示距离或不可配送原因。

### 2.3 个人资料与账号安全

- 新增昵称更新、头像上传、手机号换绑和密码修改接口及移动端页面。
- 头像仅接受 JPEG、PNG、WebP，最大 2 MiB；服务端解码真实图片并限制最长边 4096 像素。
- 对象名使用 `user-avatar/{userId}/{uuid}.{ext}`，不接受身份证号或外部头像 URL 输入。
- 换绑手机号分别验证原手机号和新手机号验证码。
- 修改密码支持当前密码或短信验证码；手机号或密码修改后撤销全部刷新会话并要求重新登录。
- 资料和敏感操作写入 `user_security_audit`；OSS 上传失败会明确失败，不再返回伪成功 URL。

### 2.4 全链路与失败恢复

- 新增实付金额全额退款 E2E，验证支付 18 元后余额从 500 元降至 482 元，取消后恢复至 500 元，并产生一笔 18 元退款入账。
- 新增支付查询临时失败 E2E，验证保留订单、人工重查恢复以及只产生一笔支付扣款。
- E2E 独立夹具补齐 `setmeal` 和 `user_search_history`，地址脚本改用三级区划代码选择。
- 修复应用启动时会话恢复失败覆盖并发注册结果的问题。
- E2E WebSocket 直连临时后端，验证断线补拉相关基础连接不被开发服务器误判为认证失败。

## 3. 旧旁路清理

- 删除开发环境演示登录/注册 Controller、DTO、配置属性和默认密码注册实现。
- 支付结果始终查询服务端支付单状态，不使用 URL 参数判断成功。
- 退款金额来自成功支付单的 `amount_cent`，不存在固定 0.01 元退款。
- 配送范围校验没有跳过分支。
- 静态检索 `默认密码 123456`、`mockPay).*success`、`new BigDecimal("0.01")`、`跳过配送范围校验` 均无结果。

## 6. 真实微信支付接入边界

资金与业务状态已通过 `PaymentGateway`、`RefundGateway` 和渠道字段隔离。后续普通手机浏览器接入微信支付时：

1. 新增微信 H5 支付网关实现，创建支付单后返回微信 `mweb_url`，前端跳转支付但不根据返回 URL 判定成功。
2. 服务端验签微信支付回调，以微信交易号和事件 ID 做幂等处理，并继续由现有支付状态查询接口向前端返回权威结果。
3. 新增微信退款网关实现，退款金额继续读取成功支付单；退款回调和主动查询共同驱动现有退款状态机。
4. 模拟余额、模拟网关和真实微信配置按环境隔离，订单、支付单、退款单和流水模型无需改写。
