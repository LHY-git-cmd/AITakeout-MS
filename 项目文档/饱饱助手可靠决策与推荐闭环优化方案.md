# 饱饱助手可靠决策与推荐闭环优化方案

> 版本：1.0  
> 日期：2026-10-03  
> 目标：让 Agent 在健康、时令、地域和个性化需求下，稳定完成“识别、约束、推荐、解释”闭环。

## 1. 结论

当前 Agent 已有意图识别、RAG、普通商品搜索、Java 推荐引擎和推荐卡片，但这些能力仍可能并行运行，导致“文字说避开、卡片却推荐”的矛盾。

本方案统一为：

```text
用户请求
→ 场景与风险识别
→ 结构化决策契约
→ 契约校验和必要追问
→ Java 二次生成硬约束
→ 工具白名单限制
→ 查询实时在售候选
→ 硬约束过滤
→ 软条件评分
→ 推荐结果一致性校验
→ Agent 解释最终结果
→ 用户加购或反馈
```

职责分工：

```text
Python Agent：理解、追问、编排、解释
Java：事实查询、规则、过滤、排序、结果裁决
MySQL：结构化数据、规则版本、审计和推荐轨迹
Qdrant/RAG：权威说明和引用依据
```

## 2. 场景与风险

### 2.1 场景

```text
GENERAL_MEAL           普通点餐
GOAL_BASED             减脂、低脂、低糖、高蛋白
ALLERGY_RESTRICTION    过敏和明确忌口
COMMON_COLD            感冒、咳嗽、喉咙不适
SEASONAL_REGIONAL      时令和地域
CONDITION_AWARE        有限慢病辅助筛选
HIGH_RISK_MEDICAL      急性症状或治疗请求
```

### 2.2 风险级别

| 等级 | 示例 | 系统行为 |
|---|---|---|
| L0 | 不知道吃什么、预算、人数 | 普通推荐 |
| L1 | 感冒、清淡、减脂 | 一般饮食辅助，不做治疗承诺 |
| L2 | 花生过敏、明确忌口 | 硬约束过滤，未知不视为安全 |
| L3 | 高血压、糖尿病 | 只使用已发布规则和已审核数据 |
| L4 | 胸痛、呼吸困难、休克、药物冲突 | 停止推荐，提示专业或急救处理 |

置信度处理：

```text
>= 0.85  进入约束生成
0.60-0.84 追问一个关键问题
< 0.60   不执行健康推荐
```

## 3. 结构化决策契约

Agent 不得只输出“建议清淡”，必须输出 JSON 契约：

```json
{
  "scene": "COMMON_COLD",
  "risk_level": "L1",
  "confidence": 0.93,
  "hard_constraints": ["NO_ALCOHOL", "NO_SPICY", "NO_HIGH_OIL", "NO_HIGH_SODIUM_PICKLED"],
  "soft_preferences": ["WARM", "LIGHT", "EASY_TO_DIGEST"],
  "allergens": [],
  "goals": [],
  "region_code": null,
  "season": "AUTUMN",
  "requires_clarification": false,
  "temporary_only": true
}
```

契约要求：

- 场景、约束、过敏原和目标必须来自受控枚举；
- JSON Schema 校验失败不得调用业务工具；
- 低置信度安全字段必须追问；
- 自由文本中的“建议避开”必须转换成结构化约束后才能影响推荐。

## 4. Java 二次裁决

Agent 输出只是候选意图，Java 必须依据场景重新生成系统约束：

```text
系统场景约束 + 用户临时约束 + 用户档案约束
→ 规范化硬约束和软偏好
```

例如 `COMMON_COLD` 自动生成：

```text
排除酒精、辛辣、高油、高盐腌制
优先温热、清淡、易消化
```

Agent 不能删除或降低系统硬约束，也不能将 `UNKNOWN` 改成 `FREE`。

硬约束在评分前执行：

```text
过敏原
用户忌口
医生明确限制
身体不适限制
停售/库存
关键营养数据缺失
```

软条件只参与排序：

```text
时令、地域、清淡、温热、易消化、低能量、预算和口味
```

## 5. 菜品适配数据

菜品和套餐需要版本化字段：

```text
spicy_level             0-5
oil_level               0-5
salt_level              0-5
temperature_type        WARM/COLD/NEUTRAL/UNKNOWN
digestibility           EASY/NORMAL/HARD/UNKNOWN
alcohol_content         NONE/POSSIBLE/CONTAINS/UNKNOWN
pickled_food            true/false/unknown
soup_base_type          LIGHT/SPICY/RICH/UNKNOWN
ingredient_codes        标准食材编码
allergen_declarations   过敏原状态
nutrition_profile       营养版本
```

模拟数据必须标记：

```text
verification_status = SIMULATED
simulation_version = SIM-MENU-V1
```

生产环境默认只读取 `VERIFIED` 数据。

## 6. 工具白名单

工具权限必须在编排层强制执行，不能只写在 Prompt 中。

普通点餐：

```text
允许 search_products、get_product_detail、add_cart_item
```

健康和时令场景：

```text
允许 get_diet_profile、recommend_personalized_meals
禁止 search_products
```

高风险医疗场景：

```text
禁止所有商品推荐工具
只返回专业咨询或急救提示
```

同一 `task_id` 只能产生一个 `recommendation_cards` 事件。第二组推荐必须被拦截，不能让前端出现互相矛盾的卡片。

## 7. Java 推荐流程

```text
1. 校验请求和幂等键
2. 读取用户档案
3. 读取已发布规则
4. 查询实时在售候选
5. 读取营养、食材和过敏原版本
6. 执行硬过滤
7. 对剩余候选评分排序
8. 保存候选轨迹和排除原因
9. 生成推荐结果快照
10. 执行一致性校验
11. 返回推荐、排除原因和来源
```

推荐结果必须包含：

```json
{
  "recommendation_id": "rec-001",
  "scene": "COMMON_COLD",
  "items": [
    {"product_id": 68, "name": "鸡蛋汤", "match_reasons": ["WARM", "LIGHT"]}
  ],
  "excluded_items": [
    {"product_id": 51, "name": "老坛酸菜鱼", "reason_codes": ["NO_HIGH_SODIUM_PICKLED", "NO_HIGH_OIL"]}
  ],
  "rule_versions": ["COMMON_COLD-V1"],
  "data_versions": {"dish_profile": "SIM-MENU-V1"}
}
```

## 8. 一致性校验

返回前必须检查：

1. 推荐商品不命中硬约束；
2. 推荐商品当前在售；
3. 推荐原因码与菜品数据一致；
4. 被排除商品不出现在推荐列表；
5. 推荐列表不重复；
6. 模拟数据带模拟提示；
7. 健康场景没有普通搜索结果；
8. 无候选时不自动放宽约束；
9. 文字解释只能引用此结果对象。

校验失败时返回 `RESULT_CONFLICT`，不展示冲突商品，并保留审计记录。

## 9. 文字回答策略

Agent 最终只能读取以下结构化事实：

- 场景和风险等级；
- 推荐商品和匹配原因；
- 排除商品和原因码；
- 数据、规则和知识来源；
- 模拟数据提示。

禁止：

- 添加 Java 未返回的菜品；
- 推荐 Java 已排除的菜品；
- 将模拟值描述为检测值；
- 使用“治疗”“治愈”“绝对安全”等表述。

## 10. 场景示例

### 10.1 感冒

```text
用户：我今天感冒了，吃什么？
→ COMMON_COLD
→ 排除酒精、辛辣、高油、高盐腌制
→ 优先温热、清淡、易消化
→ Java返回一组推荐
→ Agent解释同一组结果
```

老坛酸菜鱼、蜀味水煮草鱼、金汤酸菜牛蛙不能因为普通搜索结果再次出现。

### 10.2 入秋

```text
用户：入秋了，最近吃什么？
→ SEASONAL_REGIONAL
→ 获取地区和当前月份
→ 读取已发布时令规则
→ 时令、温热、清淡作为软偏好
→ 过敏、忌口、库存仍是硬约束
→ Java排序后返回一组推荐
```

没有地区或时令数据时，应追问或使用通用规则，不得伪造当地当季食材。

## 11. 降级策略

| 情况 | 行为 |
|---|---|
| 场景置信度低 | 追问，不推荐 |
| 关键数据缺失 | 显示信息不足，不声称安全 |
| 规则未发布 | 返回规则不可用 |
| 没有满足硬约束的商品 | 返回无匹配，不放宽规则 |
| Java推荐服务不可用 | 不用普通搜索冒充健康推荐 |
| RAG不可用 | 可展示结构化结果，不扩展健康结论 |
| LLM不可用 | 返回模板化结构化推荐 |
| 结果冲突 | 不展示商品，记录 `RESULT_CONFLICT` |

## 12. 权限、隐私、幂等和审计

- 健康档案默认不采集；
- 支持仅本次使用；
- 读取长期档案需要用户授权；
- 推荐请求必须使用 `Idempotency-Key`；
- 保存场景、约束、规则版本、数据版本和原因码；
- 不保存模型思维过程；
- 用户只能读取自己的档案和推荐记录；
- 规则发布、模拟数据导入和真实数据替换必须审计。

## 13. 测试计划

### Agent

- 感冒识别为 `COMMON_COLD`；
- 入秋识别为 `SEASONAL_REGIONAL`；
- 低置信度触发追问；
- 高风险请求不调用商品工具；
- 健康场景工具白名单生效；
- 同一任务只有一组推荐卡片。

### Java

- 场景规则生成；
- 过敏和忌口硬过滤；
- 感冒排除辛辣、油重、腌制和酒精；
- 时令和地域评分；
- 原因码和数据一致；
- 无候选不放宽约束；
- 模拟数据开关隔离；
- 推荐结果冲突拦截。

### 端到端

```text
感冒 → 只调用健康推荐工具 → 不出现酸菜鱼 → 只产生一组卡片
入秋 → 读取地区/月份 → 时令排序 → 文字和卡片一致
花生过敏 → UNKNOWN不通过 → 不出现普通搜索结果
高血压且规则未发布 → RULES_UNAVAILABLE
急性危险症状 → PROFESSIONAL_HELP
```

## 14. 实施阶段

### 阶段一：修复矛盾

- 增加 `COMMON_COLD` 和 `SEASONAL_REGIONAL`；
- 健康场景强制工具白名单；
- 禁止健康场景调用 `search_products`；
- 单任务只允许一组推荐卡片；
- 增加结果一致性校验。

### 阶段二：补充适配数据

- 增加辣度、油量、盐分、易消化、温热、腌制和酒精属性；
- 导入 `SIMULATED` 数据；
- 补齐感冒和时令规则。

### 阶段三：统一解释

- Java返回推荐事实和排除原因；
- Agent只解释结果对象；
- 前端展示推荐、排除原因、来源和模拟提示。

### 阶段四：测试与灰度

- 执行安全评测集；
- 开发环境开启模拟数据；
- 生产默认关闭模拟数据；
- 真实数据审核后再开放慢病场景。

## 15. 完成定义

以下条件全部满足才算完成：

1. 感冒不会返回被排除的酸菜鱼等商品；
2. 入秋请求先读取时令和地区条件；
3. 健康场景不会调用普通搜索；
4. 同一任务只有一组推荐卡片；
5. 文字和卡片来自同一结果对象；
6. 推荐可还原规则、数据和版本；
7. 无数据、无规则、无候选时安全降级；
8. 模拟数据和真实数据严格隔离；
9. 高风险医疗请求不进入商品推荐；
10. 关键安全测试全部通过。
