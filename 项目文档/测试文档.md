# 测试手册

建议按以下顺序测试。前四组不会调用真实 LLM，最后一组才会产生模型费用。

---

```powershell

```

**预期：**


### 前端


## 4. 启动真实测试环境

**注意：** 请使用测试密钥，不要把真实密钥提交进 Git。

启动前至少配置环境变量：

```powershell
# 数据库与缓存
$env:MYSQL_USER = "sky"
$env:MYSQL_PASSWORD = "test-password"
$env:MYSQL_ROOT_PASSWORD = "test-root-password"
$env:DB_USERNAME = "sky"
$env:DB_PASSWORD = "test-password"
$env:REDIS_PASSWORD = "test-redis-password"

# JWT 密钥
$env:JWT_ADMIN_SECRET = "replace-with-long-test-secret"
$env:JWT_USER_SECRET = "replace-with-long-test-secret"

# AI 服务
$env:AI_ENABLED = "true"
$env:LLM_PROVIDER = "deepseek"
$env:LLM_BASE_URL = "`https://api.deepseek.com`"
$env:LLM_MODEL = "你的实际模型名称"
$env:LLM_ALLOWED_MODELS = $env:LLM_MODEL
$env:LLM_API_KEY = "你的测试API-Key"

# Embedding 模型
$env:BGE_MODEL_HOST_PATH = "BGE-M3模型所在目录"
```

### 启动服务

启动完整链路及观测组件：

```powershell
docker compose --profile observability up -d --build
docker compose ps
```

**预期：**
等待所有核心服务变为 `healthy`，Embedding 首次启动可能耗时较长。

### 健康检查

```powershell
Invoke-RestMethod http://localhost:8001/health/ready
Invoke-RestMethod http://localhost:8000/health/ready
Invoke-RestMethod http://localhost:8080/actuator/health/readiness
```

### 指标检查

```powershell
(Invoke-WebRequest http://localhost:8001/metrics).Content
(Invoke-WebRequest http://localhost:8000/metrics).Content
(Invoke-WebRequest http://localhost:8080/actuator/prometheus).Content
```

### 浏览器访问

- **Prometheus：** `http://localhost:9090`
- **Grafana：** `http://localhost:3000`

在 Prometheus 的 `Status → Targets` 中确认 Java、Agent、Embedding、Qdrant 均为 `UP`。

## 5. 真实 LLM 流式调用

直接调用 Agent：

```powershell
$taskId = "manual-" + [guid]::NewGuid().ToString("N")
$traceId = "trace-" + [guid]::NewGuid().ToString("N")

$body = @{
    user_id     = 1
    task_id     = $taskId
    trace_id    = $traceId
    session_id  = "manual-session"
    query       = "请用一句话说明什么是RAG"
    model       = $env:LLM_MODEL
    temperature = 0.2
} | ConvertTo-Json

$result = Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:8000/api/v1/agent/submit" `
    -ContentType "application/json" `
    -Body $body

$result
curl.exe -N $result.stream_url
```

**预期 SSE 顺序：**
1.  `task_start`
2.  `token`
3.  `token`
4.  ...
5.  `task_end`

### 查看任务状态

```powershell
Invoke-RestMethod "http://localhost:8000/api/v1/agent/status/$taskId"
```

## 6. 取消链路测试

提交一个较长生成任务，然后立即执行：

```powershell
Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:8000/api/v1/agent/tasks/$taskId/cancel"
```

**预期：**
- 状态变为 `cancelled`。
- SSE 收到 `task_cancelled`。
- 前端显示“已停止生成”。
- 后续不再输出 Token。

也可以在管理端 AI 助手页面直接点击“停止生成”，验证 `前端 → Java → Python Task → LLM Stream` 整个取消链路是否成立。

---

## 7. 日志与追踪测试

使用刚才的 `$traceId` 和 `$taskId` 查询日志：

```powershell
docker compose logs sky-server sky-agent sky-embedding | Select-String $traceId
docker compose logs sky-server sky-agent sky-embedding | Select-String $taskId
```

**预期：**
如果问题启用了知识库检索，应该能通过相同的 `trace_id`/`task_id` 关联 Java、Agent、Embedding 和 LLM 调用。

---

## 8. 测试后清理

测试结束后停止服务：

```powershell
docker compose --profile observability down
```

**注意：** 不要附加 `-v`，否则会删除 Compose 数据卷。
